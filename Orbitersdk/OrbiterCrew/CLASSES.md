# «Экипаж» — логические классы (проект, 2026-10-01)

Основа — **Человек**. Каждый класс ниже описан через своё отношение к нему. Это проект для согласования между «Экипажем» и «Скафандром» до начала перестройки (шаг 2 в PLAN.md); код пока не меняется.

## 0. Главное разделение

- **Человек — не корабль Orbiter.** Это обычный объект (данные + логика организма), который может находиться в разных местах.
- **Корабль Orbiter нужен только там, где человек виден и движется сам:**
  - **Аватар** — человек снаружи (сегодняшний `CrewMember`);
  - **Экзоскелет** — машина, в которой сидит человек;
  - **Груз**, лежащий отдельно;
  - **Ранец**, сброшенный отдельно.
- Когда человек на корабле, его аватара нет: человек живёт в списке экипажа и в месте у порта корабля.

```
Реестр экипажа ─┬─ Человек ── Организм, Способности, Кто
                │     │ где: Аватар | Место на корабле | Место в экзоскелете
                │     │ надето: Одежда (Комбинезон | Скафандр кл.1/кл.2) ── Компьютер, Аналоговый контур, Порт ранца ── Ранец
                │     │ несёт: Груз
                └─ Среда (Атмосферы, Радиация, Тепло, Гравитация) ── Окружение в точке
```

## 1. Человек (`Person`) — «Экипаж»

| Часть | Что внутри |
|---|---|
| `Identity` | имя, роль, пол, возраст, масса, рост, модель (skin + клипы), голос |
| `Abilities` (производные) | `AerobicMax()`, `Strength()`, `LiftCapacity()`, `RunLimit()` — от пола, возраста, массы и с поправкой на состояние организма |
| `Organism` (сегодняшний `Body`, расширенный) | **запасы:** вода, энергия (гликоген, жир), кислородный резерв мозга; **нагрузка:** метаболизм, выносливость (W′), пульс, дыхание, температура тела; **поражения:** травмы, доза за выход и за карьеру, обезвоживание, голод; **итог:** `OK / ослаблен / без сознания / мёртв` |
| `Location` | `Avatar*` / `Seat*` (на корабле или в экзоскелете) |
| `Worn` | **слои:** внутренний `Garment*` (комбинезон — всегда) + внешний `Garment*` (скафандр, если надет) |
| `Carried` | `Cargo*` в руках (или нет) |

```cpp
struct Exposure {            // что реально доходит до тела за этот шаг (после надетого)
    double ppO2, ppCO2;      // вдыхаемое, кПа
    double ambientP;         // давление снаружи всего надетого (вакуум без скафандра — смерть)
    double pIn;              // давление у тела (в скафандре), кПа: декомпрессия, кессонная болезнь, утечка
    double tAir;             // температура воздуха у тела, K: комфорт и пот (heatW один её не заменяет)
    double leak;             // скорость утечки газа из скафандра (0 — герметичен)
    double heatW;            // тепло, которое одежда не отвела (+ греет, − охлаждает)
    double doseRate;         // Зв/ч (Shield считает через Radiation::Dose(env, г/см², поле))
    double g, accelG;        // гравитация, перегрузка
    double impact;           // м/с удара на этом шаге (0 — не было)
};
struct Supply {              // что человек может взять на этом шаге
    double water, food;      // кг, доступно (из скафандра или с корабля)
};
struct BodyOutput {          // что тело отдало на этом шаге
    double o2Use, co2Made;   // кг/с
    double heatW, sweat;     // Вт, кг/с воды
    double drink, eat;       // кг/с, сколько взял
};

class Person {
public:
    void Step(double dt, double activityW, const Exposure& in, Supply& supply, BodyOutput& out);
    Abilities Can() const;             // текущие способности
    const Organism& Body() const;
    void Save(FILEHANDLE) const; bool Load(const char* line);
};
```

**Человек ничего не знает о том, что на нём надето и где он стоит.** Он получает `Exposure` и `Supply` и отдаёт `BodyOutput`.

## 2. Среда (`Environment`) — «Экипаж»

`EnvSample Sample(const VESSEL* where)`:
- **воздух:** давление, температура, состав (O₂, CO₂ — из `Atmospheres.cfg`);
- **гравитация;**
- **радиация:** компоненты из `Radiation`;
- **тепло:** солнце или тень, температура грунта.

Одна точка — одна выборка. Её используют и аватар, и экзоскелет, и (позже) корабль для кабины.

## 3. Надеваемое — общий интерфейс (согласовать до шага 2)

```cpp
class Garment {                         // комбинезон, скафандр кл.1, кл.2
public:
    virtual double Mass() const = 0;
    virtual bool   Sealed() const = 0;               // герметичен (можно в вакуум)
    // главное: среда снаружи + то, что отдало тело -> что доходит до тела; тратит свои ресурсы
    virtual Exposure Filter(const EnvSample& env, const BodyOutput& body, double dt) = 0;
    virtual void   Provide(Supply& s) {}             // вода из запаса скафандра
    virtual AssistResult Assist(const Activity& a, double humanW) { return { humanW, 0 }; }   // приводы
    virtual PackPort* Port() { return nullptr; }     // есть ли крепление ранца
    virtual SuitComputer* Computer() { return nullptr; }
    // носимое меняет хост (аватар или экзоскелет): масса, PMI, точки касания, свои двигатели (N2 РСУ, ранец), частицы
    virtual void Attach(VESSEL4* host) {} virtual void Detach() {}
    virtual void Save(FILEHANDLE) const = 0; virtual bool Load(const char* line) = 0;   // ключи строк уникальны по владельцу
};
struct Activity { double speed, grade, carriedKg, g; int gait; };   // что делает человек: для приводов
struct AssistResult { double humanW, driveW; };                      // сколько осталось человеку, сколько берут приводы с шины

class PackPort {                          // крепление ранца на скафандре; аватар говорит с ранцем через него
public:
    virtual double Thrust() const = 0;    // текущая тяга (для взлёта и полёта)
    virtual void   Touchdown() = 0;       // аватар зовёт при касании грунта: гасит все сопла, включая ориентацию
    virtual bool   SurfaceMode() const = 0;
};
```

- **Слои надетого:** внутренний — комбинезон (всегда), внешний — скафандр (если надет). `Filter` идёт цепочкой: среда → внешний → внутренний → `Exposure`. Комбинезон под скафандром нужен для тепла и пота, и чтобы человек в шлюзе без скафандра был в комбинезоне.

- **`Coverall` (комбинезон) — «Экипаж».** Почти прозрачный: 0,3 г/см², воздух снаружи, своего запаса нет.
- **`Suit` (кл. 1 «Каркас», кл. 2) — «Скафандр».** Внутри:
  - `AnalogLoop` — давление, O₂, CO₂, термостат, лампы; работает без компьютера;
  - `PowerBus` (батарея, потребители), баки (O₂, вода, поглотитель);
  - `Thermal`, `Drives`, `Shield` (пассив + поле);
  - `SuitComputer` (обособленный узел);
  - `PackPort`.
- **Класс скафандра — данные, а не код.** Масса, защита г/см², поле, тепловой допуск, мощность приводов, баки и анимационный слой задаются конфигом класса. Кл. 2 — тот же `Suit` с другими числами и своим слоем «тяжёлого шага».

## 4. Компьютер скафандра (`SuitComputer`) — «Скафандр»

- **Принадлежит скафандру, но обособлен:** своё питание от шины, своё состояние (`ОК / сбой / выключен`), свои отказы (поломка, питание, доза).
- **Входы:** `SuitSensors` — сводка скафандра (баки, шина, тепло, поле), биодатчики человека (пульс, дыхание, температура тела, доза) и навигационный датчик `const VESSEL* host` только для чтения (положение, скорость, окружающие корабли и базы, рельеф).
- **Экран:** аватар передаёт компьютеру отрисовку и клики: `Draw(oapi::Sketchpad*, const HUDPAINTSPEC*)`, `Click(x, y)` — из `clbkDrawHUD` и ввода мыши.
- **Выходы:** только команды скафандру и ранцу (`SuitCommands`, `PackCommands`).
- **Внутри:** экран (сегодняшний `SuitHud`), предупреждения и тренды, навигация и цели, автопилоты (`Autopilot`), помощник ранца, оптимизация расхода.
- **Отказ:** экрана нет, только лампы аналогового контура; автопилоты и помощник выключены; аналоговый контур держит жизнь грубее и с большим расходом.

## 5. Ранец (`Pack`) — «Скафандр»

- Подключается к `PackPort` скафандра, а не к человеку. Через `Attach(host)` создаёт свои двигатели и частицы, меняет массу, PMI и точки касания хоста.
- Сам «глупый»: ручные входы → тяга. Умным его делает компьютер через `PackCommands`.
- Масса и топливо: **металлический водород** в сменном сосуде (решение пользователя 2026-10-01). Дальность — прыжками на безатмосферных телах; сменный сосуд — как «Груз»/заправка.
- Сброшенный — отдельный корабль Orbiter (как сейчас `JetPack.cfg`).

## 6. Экзоскелет (`Exoskeleton`, кл. 3) — «Скафандр»

- **Не надевается — принимает.** Отдельный корабль Orbiter со своим местом (`Seat`): человек в любой одежде садится в него.
- **Своё:** энергия, грузоподъёмность (на порядок выше человека), шагающая механика и анимация.
- **Человеку отдаёт** `Exposure` (если кабина закрыта — свою, иначе пропускает через одежду) и берёт на себя нагрузку.

## 7. Груз (`Cargo`) — «Экипаж»

- **Данные:** масса, размер, точки хвата; может быть хрупким.
- **Состояния:** лежит (свой корабль Orbiter) / в руках человека / в экзоскелете / в трюме.
- **Погибший человек становится грузом:** аватар превращается в груз в точке гибели (масса тела + надетого, вид — тело), его можно поднять, донести и доставить на корабль. Человек в реестре остаётся с отметкой «погиб».
- **В руках:** добавляет массу; цена в выносливости растёт по экспоненте от доли грузоподъёмности; позже — слой анимации «несёт».
- **Грузоподъёмность** берётся у того, кто несёт: человек (`LiftCapacity` от пола, возраста, состояния) + приводы скафандра (`Assist`) или экзоскелет.

## 8. Места и корабли (`Seat`, `ShipAdapter`) — «Экипаж»

- **`Seat`** — место, где сидит человек: на корабле у настроенного порта или в экзоскелете. Отдаёт человеку `Exposure` (воздух кабины) и `Supply` (вода, еда); принимает `BodyOutput` (расход).
- **`ShipAdapter`** — описание чужого корабля конфигом по имени класса, без его кода:
  - порты и шлюзы (положение, направление, давление);
  - места;
  - кабина (объём, воздух);
  - запасы (O₂, вода, еда, энергия, зарядка скафандров).

  Расход запасов считает наш модуль. Корабли, которые хотят больше, подключаются небольшим API.
- **`ChargeStation`** — отдельная станция зарядки: точка подключения + запас энергии.

## 9. Реестр экипажа (`CrewRegistry`) — «Экипаж»

- Все люди в симуляции и где каждый: аватар, место на корабле, место в экзоскелете.
- Выход: место на корабле → аватар у шлюза. Вход: аватар → место. Переход между пристыкованными кораблями.
- Сохранение: аватар — в своём сценарии; люди на кораблях — **открытый вопрос:** чужой корабль не пишет наши строки в сценарий; варианты — свой файл рядом со сценарием или модуль-плагин Orbiter.

## 10. Аватар (`Avatar`, сегодняшний `CrewMember`) — «Экипаж» (кроме подключения скафандра)

Корабль Orbiter для человека снаружи:
- **держит** `Person*` и его `Garment*`;
- **физика:** ходьба по поверхности, прыжок, падение, полёт (тягу даёт ранец);
- **вид:** `Skin`, `Motion`; звук: `Sound`;
- **ввод.**

**Шаг кадра** (порядок важен: компьютер до ранца, ранец до контакта с грунтом):
```
env   = Environment.Sample(this)
exp   = outer->Filter(env, …) → inner->Filter(…)    // цепочка слоёв; на lastBodyOut (лаг в один шаг — допустим)
outer/inner->Provide(supply)
computer->Step(sensors)                              // если жив; иначе лампы
pack->Update(commands или ручной ввод)
физика аватара: контакт с грунтом, касание (pack->Touchdown()), взлёт
a     = outer->Assist(activity, humanW)
person->Step(dt, a.humanW, exp, supply, lastBodyOut)
Motion / Skin / Sound — по состоянию человека и надетого
```
