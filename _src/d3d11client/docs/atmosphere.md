# Атмосферы планет

[← оглавление](DEVELOPER.md)

Состояние кода: 21.10.2026

Глава описывает физическую атмосферу клиента («FX-атмосфера»): модель рассеяния, таблицы, проход неба и
атмосферной перспективы, свет неба для остальных шейдеров, Солнце и адаптацию глаза, а также старую простую
систему неба/дымки, которую FX-атмосфера заменяет. Номера строк — по файлам на дату выше; при расхождении искать по
имени функции.

## 1. Назначение и место в кадре

### 1.1. Что делает система

- Рисует небо с земли, дымку (атмосферную перспективу) на тайлах и кораблях, атмосферу планеты из космоса (лимб,
  терминатор, сумерки) — один полноэкранный проход на каждую планету с атмосферой в поле зрения.
- Даёт всем шейдерам клиента свет в точке: прямое Солнце через воздух (`FxSunLight`) и свет неба (`FxSkyLight`,
  с поправкой по реальному небу в SH).
- Считает адаптацию глаза (экспозицию и цветовой баланс) по освещённости у камеры и видимость звёзд.

### 1.3. Проход атмосферы (`Atmosphere::Render`, `FxAtmo.cpp:484-583`)

- Отбор планет (`FxAtmo.cpp:494-506`): все `PlanetAtmosphere` с готовыми таблицами; если камера вне верхней границы,
  планета берётся при угле между направлением взгляда и центром ≤ `diag + asin(Rt/dist) + 0.01` (`diag` — полудиагональ
  поля зрения). Сортировка — дальние первыми (`FxAtmo.cpp:508`).
- `gc->ResolveDepth()` — при MSAA `depthSRV` разрешается только по запросу (`FxAtmo.cpp:509`).
- Цель — текущая RTV (HDR FP16) без DSV; глубина читается как текстура `t0` (`FxAtmo.cpp:517-529`).
- Смешивание — **dual-source** (`bsDual`, `FxAtmo.cpp:286-293`): `SrcBlend = ONE`, `DestBlend = SRC1_COLOR`,
  `BlendOp = ADD`, запись только RGB. Итог: `цвет = add + сцена × mul` поканально, где `add` = `SV_Target0`
  (рассеянный свет), `mul` = `SV_Target1` (пропускание).
- Геометрия — полноэкранный треугольник (`Draw(3)`, `fx_atmo.hlsl:34-39`), `rsNone`, `dsRead`.
- Для планеты, внутри атмосферы которой камера (`a == current && alt < top`), сначала диспатчится `CSVol`
  (объём атмосферной перспективы), затем PS берёт из него значения (`FxAtmo.cpp:545-570`). Иначе (из космоса и для
  остальных планет) PS сам интегрирует луч за 48 шагов.
- После всех планет восстанавливаются свет текущей планеты (`BindLight`), `bsOpaque` и DSV (`FxAtmo.cpp:577-582`).

### 1.4. Когда строятся таблицы

- Таблицы одной планеты строятся **один раз** в первом кадре после создания её `PlanetAtmosphere`
  (`Frame`: `if (!a->tablesReady) a->BuildTables(...)`, `FxAtmo.cpp:364`). Создание — при первом проходе по
  `g_fxPlanets` (все планеты клиента, независимо от расстояния).
- Таблицы не зависят от положения Солнца и камеры (параметризованы по `r`, `mu`, `muS`), поэтому не пересчитываются.
  Изменение `.atmo.cfg` вступает в силу после перезапуска сессии (или после `Release` + `Init` при смене устройства).
- Объём атмосферной перспективы пересоздаётся при смене размера сцены (`EnsureVolume`, `FxAtmo.cpp:461-480`).
- SH неба пересчитываются каждый кадр (`UpdateSkySH`, `FxAtmo.cpp:323-340`), если камера внутри атмосферы.

### 1.5. Включение

`Config\D3D11Client\Fx.cfg`, ключ `Atmosphere` (`Fx.cpp:19-32`): `0` — FX-атмосфера выключена, работает старая
система; `1` или отсутствие файла/ключа — включена. При сбое `Atmosphere::Init` (не скомпилировался хотя бы один из
`VS`, `PS`, `CSTrans`, `CSMS`, `CSIrr`) атмосфера тоже выключается (`atmoOk = false`). `CSVol` и `fx_sky_sh.hlsl`
необязательны: без них PS интегрирует каждый пиксель, а `FxSkyLight` обходится без SH.

## 2. Физическая модель

### 2.1. Источники

Указаны в коде: Hillaire 2020, «A Scalable and Production Ready Sky and Atmosphere Rendering Technique» (схема
таблиц, приближение многократного рассеяния, объём атмосферной перспективы); Bruneton 2017, «Precomputed Atmospheric
Scattering: a New Implementation» (параметризация таблицы пропускания, эталонные коэффициенты Земли); Cornette-Shanks
(фазовая функция аэрозоля); Ramamoorthi & Hanrahan (свёртка SH с косинусом). Источники данных по планетам — в
комментариях `.atmo.cfg` (§4).

### 2.2. Единицы

- Длины — метры, коэффициенты — 1/м. Три канала RGB; длины волн каналов указаны в шапке каждого `.atmo.cfg`
  (Земля 680/550/440 нм, Марс и Венера ~610/550/465, Титан ~650/560/480).
- Освещённость от Солнца вне атмосферы = 1 (белое Солнце клиента).
- В таблицах и `FxMarch` яркость — физическая (при Солнце = 1). На экран идёт `π × яркость`: белая ламбертова
  поверхность под Солнцем даёт 1 (`fx_atmo_light.hlsli:4`, `fx_atmo.hlsl:262`).

### 2.3. Среда (`AtmoMedia`, `FxAtmo.cpp:79-89`; GPU — `fx_atmo_light.hlsli:56-73`)

Высота `h` — над радиусом планеты `R` (`oapiGetSize`).

- Рэлеевская плотность: `ρR(h) = exp(-h/HR)`; при `RayleighBreak = hb > 0` и `h > hb`:
  `ρR(h) = exp(-hb/HR - (h-hb)/HR2)` (двухступенчатый профиль, Венера). Код: `RayDensity`, `FxRayDensity`.
- Аэрозоль: без слоя (`MieLayer` не задан, `mieBase < 0`) — `ρM(h) = exp(-h/HM)`. Со слоем `[base, top]`:
  ниже `base` — `exp(-(base-h)/1000)` (нижний край ~1 км), внутри — 1, выше — `exp(-(h-top)/HM)`.
  Код: `MieDensity`, `FxMieDensity`.
- Поглотитель (озон): «палатка» `ρA(h) = max(0, 1 - |h - hc| / hw)`; при `hw = 0` поглотителя нет.
  Код: `FxAbsDensity`.
- Коэффициенты: `σR = RayleighScatter × ρR` (только рассеяние), `σM,ext = MieExt × ρM`,
  `σM,sca = MieExt × MieSSA × ρM` (`mieSca` считается на CPU, `FxAtmo.cpp:139`), `σA = AbsorbExt × ρA`.
- Полное ослабление: `σt(h) = σR + σM,ext + σA` (`FxExtinction`).

### 2.4. Фазовые функции (`fx_atmo_sky.hlsli:13-18`, копия в `fx_atmo_lut.hlsl:18-23`)

- Рэлей: `pR(c) = 3/(16π) (1 + c²)`, `c` — косинус угла рассеяния.
- Аэрозоль, Cornette-Shanks с поканальным `g`:
  `pM(c) = 3/(8π) (1 - g²)(1 + c²) / ((2 + g²)(1 + g² - 2gc)^1.5)`; знаменатель ограничен снизу `1e-4`.
  В шапке `sun.hlsl` и в комментариях упоминается Henyey-Greenstein; в рассеянии атмосферы используется именно
  Cornette-Shanks. HG применяется только в оценке ореола (`Aureole`, `common.hlsli:138-146`).

### 2.5. Пропускание и оптическая толща

`T(r, mu) = exp(-τ)`, `τ = ∫ σt(h(t)) dt` от точки радиуса `r` в направлении с косинусом зенитного угла `mu` до
верхней границы `Rt = R + Top`. Считается в таблице (`CSTrans`, §3.1). Функция Чепмена не используется: везде прямое
численное интегрирование.

К Солнцу (`FxTransToSun`, `fx_atmo_light.hlsli:87-93`): `T(r, muS) × smoothstep(-e, e, muS - cosH)`, где
`cosH = -sqrt(1 - (R/r)²)` — косинус геометрического горизонта, `e = max(угловой радиус Солнца, 1e-4)`. Это даёт тень
планеты в воздухе и плавный заход диска. Рефракция не моделируется.

### 2.6. Однократное рассеяние вдоль луча (`FxMarch`, `fx_atmo_sky.hlsli:28-60`; `Step` в `fx_atmo.hlsl:92-108`)

На каждом отрезке `[ta, tb]` с серединой `tm`:

```
S  = σR (Ts·pR + Ψms) + σM,sca (Ts·pM + Ψms)       Ts = FxTransToSun(r, muS), Ψms = таблица MS
a  = exp(-σt·dt)
L += T · (S - S·a) / σt                             (аналитический интеграл при постоянных S, σt на отрезке)
T *= a
fwd += σM,sca · g² · dt
```

Геометрия луча задаётся от точки наибольшего сближения: `tc0 = -dot(org, d)`, `K = |org × d|² - R²`,
`r(t)² - R² = K + (t - tc0)²`; высота `h = q / (r + R)` при `q = K + (t-tc0)²` — без вычитания больших чисел,
одинаково устойчиво для камеры у земли и для планеты в миллионе км. `h` ограничена снизу −2000 м (моря Титана ниже
среднего радиуса). Шаги сгущаются квадратично к точке сближения (`n1` шагов до неё, `n2` после).

`fwd` — оптическая толща прямого пика аэрозоля (приближение delta-scaling с долей `f = g²`): изображение за воздухом
умножается на `T × exp(min(fwd, 40))` (`fx_atmo.hlsl:261`), т.е. свет, рассеянный аэрозолем вперёд, не вычитается из
изображения.

### 2.7. Многократное рассеяние (`CSMS`, `fx_atmo_lut.hlsl:89-133`)

Приближение Hillaire 2020: порядки выше первого — изотропный источник, зависящий от `(r, muS)`.

Для точки `(r, muS)`: 64 направления сферы Фибоначчи (`SphereDir`), по каждому 40 равных шагов до земли или границы.

```
L  = ∫ T · Ts · σs / (4π) dt   (+ T · Ts(R, mu)·max(mu,0) · albedo / π, если луч упёрся в землю)
F  = ∫ T · σs dt
L2 = mean(L), f = min(mean(F), 0.99)
Ψms = L2 / (1 - f) + DiffuseBelow(r, muS) / π
```

`σs = σR + σM,sca`. `L2/(1-f)` — сумма геометрического ряда порядков.

`DiffuseBelow` (`fx_atmo_lut.hlsl:72-87`) — добавка для толстого столба (облака Венеры, τ ~30), которую ряд
изотропных порядков не переносит. Двухпотоковая оценка по столбу над точкой (64 шага):
`τ' = Σ (σR + σM,ext - σM,sca·g) dh` (транспортная толща, у Рэлея `g = 0`),
`τa = Σ (σM,ext - σM,sca + σA) dh` (поглощение),
`Tt = exp(-sqrt(3 τa τ')) / (1 + 0.75 τ')`; вес `w = saturate((τ' - 1)/3)`; результат
`w · Tt · saturate((muS + 0.1)/1.1)` — поток на горизонтальную площадку, в таблицу идёт как изотропная яркость `/π`.
Для тонкого воздуха (`τ' ≤ 1`, Земля, Марс) добавка равна нулю. По формуле она действует и у поверхности Титана
(оценка по `Titan.atmo.cfg`: `τ'` в зелёном ~3.4, вес ~0.8).

### 2.8. Освещённость от неба (`CSIrr`, `fx_atmo_lut.hlsl:136-178`)

Для `(r, muS)`: 64 направления верхней полусферы, распределённые по косинусу; по каждому `SkyRadiance` (32 шага,
квадратичное сгущение к началу, однократное + `Ψms`); `E = π · mean(L)`. Отражение от земли в `E` не входит; оно
добавляется в `FxSkyLight` отдельно.

### 2.9. Земля

- Под лучом, упёршимся в землю (сфера `R`): `L += T · albedo/π · (Ts·max(muS,0) + E(R, muS))`
  (`FxSkyRadianceEx`, `fx_atmo_sky.hlsli:84-88`; `GroundFill`, `fx_atmo.hlsl:72-79`).
- В проходе атмосферы камера внутри воздуха получает «землю-заливку» на сфере `R - 1 км` там, где тайлы не нарисованы
  (`MakeRay`, `fx_atmo.hlsl:60-63`); пропускание за ней 0.
- В `FxSkyLight` свет от земли снизу: `G = albedo · (E + Ts·max(mu, 0))`.

### 2.10. Свет в точке для шейдеров клиента (`fx_atmo_light.hlsli:101-128`)

- `FxSunLight(wp)`: вне атмосферы 1; внутри — `FxTransToSun(r, muS)`.
- `FxSkyLight(n, wp)`: вне атмосферы 0.02 (слабая заливка как в старой системе); внутри
  `iso = E·(0.5 + 0.5k) + G·(0.5 - 0.5k)`, `k = dot(n, up)`, плюс `0.02 × (h / Top)` (заливка, растущая к границе).
  Если SH действительны (`tFxSH[9].w > 0.5`) и точка не дальше 5 км по радиусу от камеры, `iso` смешивается с
  `FxSHIrradiance(n)` с весом `1 - |r - r_cam| / 5000`.
- Обёртки `SunLight`, `SkyLight` в `common.hlsli:121-130` вызывают их при `FxActive()`.

### 2.11. Свет неба в сферических гармониках (`fx_sky_sh.hlsl`)

Каждый кадр, один поток-группа из 256 потоков: 1024 направления сферы Фибоначчи (глобальная система, ось `z` —
«полюс» базиса). Выше местного горизонта — `FxSkyRadianceEx(камера, d, 10 шагов, aboveOnly) / π`; ниже — яркость
земли под камерой `albedo/π · (Ts·max(muS,0) + E)` (земля берётся на радиусе камеры: средний радиус может лежать выше
камеры над морем). Проекция на 9 функций L2, вес `4π/1024`, свёртка с косинусом:
`A = {π, 2π/3 ×3, π/4 ×5}`. Результат — освещённость (`E` при Солнце = 1), `uSH[0..8].rgb`; `uSH[9] = (r_cam, 0, 0, 1)`.
Вычисление (`FxSHIrradiance`) — 9 произведений (`fx_atmo_light.hlsli:35-42`).

### 2.12. Ореол (`common.hlsli:132-166`)

Не часть таблиц: оценка доли света неба, приходящей из конуса вокруг Солнца, по средней `g` аэрозоля (HG):
угол конуса половинной интенсивности, энергия HG в конусе, доля аэрозоля в рассеянии по каналам. `SkyLightShaded`
затеняет эту долю по каскадам теней (`AureoleVis`). Используется в `planet.hlsl:302`, `mesh.hlsl:205, 217`.

### 3.1. Параметризация

Пропускание (`FxTrans`, `fx_atmo_light.hlsli:76-85`; построение — `CSTrans`, `fx_atmo_lut.hlsl:41-59`):

```
Hh   = sqrt(Rt² - R²)                  (mGeo.y)
rho  = sqrt(r² - R²),  xr = rho / Hh
d    = -r·mu + sqrt(Rt² - r²(1 - mu²))   (расстояние до границы)
dmin = Rt - r,  dmax = rho + Hh,  xm = (d - dmin) / (dmax - dmin)
```

При построении `mu = (Hh² - rho² - d²) / (2 r d)`, интеграл — 600 шагов по средней точке. Выборка — `xm·(TW-1)`,
`xr·(TH-1)` (центры текселей на краях совпадают с узлами).

MS и освещённость: `x = muS·0.5 + 0.5`, `y = FxAltX(r) = sqrt((r - R)/(Rt - R))` — строки сгущены у земли
(`fx_atmo_light.hlsli:26-29`). Обратное — `FxAltR`. При построении `r` зажат в `[R+1, Rt-1]`.

Фильтрация — ручная билинейная `FxBilinear` через `Load` (сэмплеры клиента не занимаются,
`fx_atmo_light.hlsli:45-53`).

Система координат ядер: центр планеты в нуле, вверх `+y`, Солнце в плоскости x-y (`fx_atmo_lut.hlsl:6`).

### 3.2. Порядок построения и привязки (`BuildTables`)

1. b4 = константы планеты (`cb`); `CSTrans` → `trans` (u0).
2. `trans` как SRV в **t8** (там шейдеры ждут `tFxLut`; строки 0..63 совпадают), `CSMS` → `ms` (u0).
3. `ms` в t1 (`tMS`), `CSIrr` → `irr` (u0).
4. Копирование `trans` и `irr` в `lut`; `tablesReady = true`; `ReadTables` — копия пропускания, освещённости и MS на
   CPU (staging) и строка в журнал (§7).

CPU-копии (`cpuTrans`, `cpuIrr`) используются в `LightAt` (освещённость горизонтальной площадки у камеры для
экспозиции, та же параметризация, что в шейдерах; `FxAtmo.cpp:216-232`).

### 3.3. Объём атмосферной перспективы (`CSVol`, `fx_atmo.hlsl:110-146`)

| Ресурс | Формат | Размер | Содержимое |
|---|---|---|---|
| `apL` (u0 / t1) | `R16G16B16A16_FLOAT`, 3D | `ceil(W/12) × ceil(H/12) × 64` | рассеянный свет до среза (×π, на экран) |
| `apT` (u1 / t2) | то же | то же | пропускание до среза × `exp(fwd)` |
| `endL` (u2 / t3) | `R16G16B16A16_FLOAT`, 2D | `ceil(W/12) × ceil(H/12)` | свет всего луча столбца (с землёй-заливкой) |
| `endT` (u3 / t4) | то же | то же | rgb — пропускание всего луча (0 за землёй или непрозрачным слоем), w — длина луча столбца [км] |

`AP_CELL = 12`, `AP_SLICES = 64` (`FxAtmo.cpp:18`). Один поток на столбец (8×8 в группе). Срез `k` лежит на
`t = t0 + (tEnd - t0)·(k/63)³` (кубически к камере), между срезами — два шага `Step`. Луч столбца идёт до верхней
границы, земли-заливки или непрозрачного слоя (без учёта сцены).

В PS для пикселя сцены на расстоянии `tS` берутся 4 ближайших столбца; в каждом срез ищется по собственной длине
луча столбца (`u = ((tS - t0)/(te - t0))^(1/3)`), затем столбцы смешиваются билинейно (`fx_atmo.hlsl:224-245`).
Одна фильтрованная выборка по столбцам разной длины давала щель вдоль горизонта (комментарий в коде).

MSAA: если глубины сэмплов пикселя различаются (край на фоне неба), воздух считается для каждого сэмпла из `t5`
(`Texture2DMS`) и усредняется (`fx_atmo.hlsl:205-223`, функция `AirAt`).

## 4. Конфигурация

### 4.1. `Config\D3D11Client\<Planet>.atmo.cfg`

Имя файла — имя планеты в Orbiter (`p->name`). Разбор — `AtmoMedia::Load` (`FxAtmo.cpp:34-65`): текст после `;`
отбрасывается, строка `Ключ = a [b [c]]`, ключ из `[A-Za-z0-9]`. Неизвестные ключи молча пропускаются. Для векторных
ключей: одно число — во все три канала; **два числа — `(a, b, a)`** (третий канал берётся из первого числа, не из
второго); три — `(a, b, c)`.

| Ключ | Поле `AtmoMedia` | Смысл | Единицы | По умолчанию |
|---|---|---|---|---|
| `Top` | `top` | высота верхней границы атмосферы | м | 0 → `12 × RayleighH` |

| `RayleighH` | `rayH` | шкала высот газа | м | 8000 |
| `RayleighBreak` | `rayBreak` | высота смены шкалы (0 — нет) | м | 0 |
| `RayleighH2` | `rayH2` | шкала высот выше `RayleighBreak` | м | 8000 |
| `MieExt` | `mieExt` | ослабление аэрозолем у земли (или внутри слоя), RGB | 1/м | 0 0 0 |
| `MieSSA` | `mieSSA` | альбедо однократного рассеяния аэрозоля, RGB | — | 0.9 0.9 0.9 |
| `MieG` | `mieG` | асимметрия фазовой функции (Cornette-Shanks), RGB | — | 0.7 0.7 0.7 |
| `MieH` | `mieH` | шкала высот аэрозоля (выше слоя — шкала спада) | м | 1000 |
| `MieLayer` | `mieBase`, `mieTop` | слой постоянной плотности `base top` (одно число: `base = top`) | м | нет (−1) |
| `AbsorbExt` | `absExt` | ослабление поглотителем в пике, RGB | 1/м | 0 0 0 |
| `AbsorbCentre` | `absCentre` | высота пика «палатки» | м | 0 |

| `GroundAlbedo` | `albedo` | альбедо земли, RGB | — | 0.1 0.1 0.1 |

#### Пример: `Earth.atmo.cfg`

```
Top             = 100000
RayleighScatter = 5.802e-6 13.558e-6 33.1e-6     ; воздух у уровня моря
RayleighH       = 8000
MieExt          = 4.44e-6 4.44e-6 4.44e-6        ; континентальный аэрозоль: рассеяние 3.996e-6, поглощение 0.444e-6
MieSSA          = 0.9 0.9 0.9
MieG            = 0.8 0.8 0.8
MieH            = 1200
AbsorbExt       = 0.650e-6 1.881e-6 0.085e-6     ; озон (полоса Шаппюи) в пике
AbsorbCentre    = 25000                          ; профиль-«палатка» 10-40 км
AbsorbHalfWidth = 15000
GroundAlbedo    = 0.1 0.1 0.1
```

Значения — эталонная Земля Bruneton 2017 (её же использует Hillaire 2020). Вертикальная оптическая толща от земли по
формулам §2.3 (оценка вручную, для сверки с журналом): Рэлей `ray·HR` = 0.046 / 0.108 / 0.265, аэрозоль
`4.44e-6 × 1200` = 0.0053, озон `AbsorbExt × hw` (площадь «палатки») = 0.0098 / 0.0282 / 0.0013; пропускание к зениту
≈ `exp(-τ)` = 0.94 / 0.87 / 0.76. Эти числа должна показать строка `atmosphere Earth tables: transmittance at the
ground to the zenith …` (§7) с точностью дискретизации.

### 4.2. Планеты без `.atmo.cfg` (`AtmoMedia::ClearGas`, `FxAtmo.cpp:67-77`)

Условие создания атмосферы — `p->atm.has && (Load || ClearGas)` (`FxAtmo.cpp:313`); `atm.has` = `oapiPlanetHasAtmosphere`
(`Planet.cpp:77-79`). Для планеты без файла:

- отказ, если `rho0 < 1e-4` кг/м³ или шкала высот `H < 100 м` («нет воздуха», Ио), либо `R > 2e7 м` (газовые гиганты:
  «земля» Orbiter у них — облачная палуба; рисуются старой системой);
- `ray = (5.802e-6, 13.558e-6, 33.1e-6) × rho0 / 1.225` — земной Рэлей, масштабированный плотностью;
- `rayH = H`, `top = min(atm.top (или 1e9), 12·H)`;
- аэрозоль, поглотитель — нет; альбедо 0.1.

Параметры берутся из `Planet::Planet` (`Planet.cpp:80-85`): `rho0 = ATMCONST::rho0`,
`H = p0 / (rho0 · g)`, `g = G·M/R²`, `atm.top = altlimit` (или `10·H`). Если в `Config\D3D11Client\<Planet>.cfg`
задан `ScaleHeight` или `Top`, они переопределяют эти значения и здесь.

Тритон (`Config\Triton.cfg`: `AtmDensity0 = 0.0001`, `AtmPressure0 = 1.45`, `AtmAltLimit = 20e3`) проходит по
`ClearGas`: порог `rho0 < 1e-4` не срабатывает только из-за строгого неравенства при равных значениях; верх — 20 км;
Рэлей ≈ 8.2e-5 земного. Отдельного файла для Тритона нет.

Наличие `.atmo.cfg` обходит отказы `ClearGas` (в том числе для газовых гигантов), но не `atm.has`: без атмосферы в
Orbiter файл не читается.

### 4.5. Старая система: `Config\D3D11Client\<Planet>.cfg` и `AtmCfg`

`AtmCfg` (`Client.h:284-289`) заполняется в `Planet::Planet` (`Planet.cpp:76-111`): `rho0`, `scaleH`, `top` из
Orbiter; цвет горизонта — `OBJPRM_PLANET_HAZECOLOUR` в линейном пространстве (`^2.2`), зенит `×0.45`, заливка `×0.4`,
Солнце белое, `hazeExt = 6.5e-5 · rho0 / 1.2`. Файл `<Planet>.cfg` переопределяет ключи `SkyHorizon`, `SkyZenith`,
`Ambient`, `Sun`, `HazeRGB`, `HazeExt`, `ScaleHeight`, `Top` (сейчас есть только `Titan.cfg`).

Старая система рисует (`common.hlsli`):

- `SkyColour(dir)` — градиент горизонт→зенит, ореол `pow(c, 24)`, `pow(c, 400)`, × «день» × ослабление с высотой;
  используется `sky.hlsl` и как запасной вариант в `liquid.hlsl`, `skypano.hlsl`;
- `ApplyHaze(col, wp)` — закон Бугера по лучу с экспонентой по средней высоте; рассеянный свет = цвет горизонта;
- `SunLight` = `gSun.rgb`, `SkyLight` = `gAmb.rgb · lerp(0.35, 1, up)` × «день».

Связь с FX-атмосферой: пока `g_fxAtmo.active` (FX-атмосфера инициализирована), `UpdateFrameCB` выключает старое небо
(`skyOn = false`), обнуляет `gAmb.w`, а `ApplyHaze` при `FxActive()` возвращает цвет без изменений. `FxActive()` =
`mGeo.z > 0.5`; `mGeo.z = 1` и в буфере планеты, и в буфере открытого космоса `cbSpace`, поэтому при включённой
FX-атмосфере `FxActive()` истинна во всех шейдерах. При `Atmosphere = 0` буфер b4 не привязывается; чтение
непривязанного константного буфера в D3D11 даёт нули, `FxActive()` = false, и работает старая система. `b0` (`gSky*`,
`gUp`, `gPlanet`) заполняется в обоих режимах; `gSky0.w` при FX остаётся признаком «камера в атмосфере по `atm.top`».

## 6. Солнце

### 6.1. Проход Солнца (`Sun.cpp:91-268`, `sun.hlsl`)

- Рисуется после непрозрачной сцены и жидкости, до прохода атмосферы (`Client.cpp:1008`): аддитивно
  (`suBS`: `ONE + ONE`, только RGB), `dsRead` с привязанным DSV — квад в глубине 0 проходит только там, где ничего не
  нарисовано (небо). Затем проход атмосферы умножает его на пропускание вдоль луча (закаты с земли и с орбиты),
  затмения получаются по глубине.
- `g_sunPassOn = true` после успешной компиляции (`Sun.cpp:129`): с этого момента `aSun.x = 0`, и проход атмосферы
  свой диск (`SunDisc`) не добавляет. Если шейдеры Солнца не собрались, диск рисует проход атмосферы.
- Квад вокруг диска до 8 радиусов Солнца (`rhoMax`) плюс 6 пикселей, во весь экран при большом угле или у края кадра
  (`Sun.cpp:141-155`). Солнце — первое тело `OBJTP_STAR`.

### 6.2. Модель (`sun.hlsl`)

| Элемент | Модель | Строки |
|---|---|---|
| фотосфера | линейное потемнение к краю `I = I0 (1 - u (1 - mu))`, `u = 0.58 / 0.69 / 0.81` (Pierce & Slaughter 1977), `I0 = Bm / (1 - u/3)` — средняя по диску = `Bm` | 349-352 |
| грануляция | ячейки ~1000 км (0.0014 радиуса), ~8 мин, видны при достаточном разрешении | 353-359 |
| пятна, факелы | процедурные группы (36 слотов), цикл 25 (минимум 2019.96, 11 лет), закон Шпёрера, закон Джоя, дифференциальное вращение (Snodgrass) | 139-171 |
| реальные карты | SDO/HMI или SOHO/MDI, GONG H-alpha, SOHO/LASCO C2 из `Modules\D3D11Client\sun\<дата>\` (`tools\sun_fetch.py`), ближайший набор в пределах 20 суток | `Sun.cpp:204-238`, `sun.hlsl:122-133` |
| хромосфера, спикулы, протуберанцы | `Bm · 1.5e-5 · (spic + 0.8·prom)`, розовый — видны только при закрытом диске | 383-408 |

### 6.3. Яркость и FP16 (`Sun.cpp:171-175`)

- Средняя яркость диска на экране `mean = 1 / a²` (`a` — угловой радиус): белая поверхность под Солнцем = 1,
  поэтому `π · L_диска = E / a²`; при 1 а.е. ~46 000.
- Пик (центр): `peak = mean / (1 - 0.81/3)` (синий канал, наибольший `I0`); при диске < 1.5 пикселя —
  `mean · discPx² / 0.72`.
- Масштаб `K = min(1, SUN_CAP / peak)`, `SUN_CAP = 3.0e4` — всё Солнце масштабируется вместе (без обрезки, потемнение и
  пятна сохраняются), чтобы пик оставался ниже предела FP16 (65504) с запасом под блик; `+INF` в постобработке дало бы
  чёрный пиксель. `Bm = mean · K` → `sPar.x`.
- Тот же предел `3.0e4` у диска прохода атмосферы (`aSun.y`) и у блика (`sun.hlsl:308`).
- Фильтр визора: плотность над диском `g_sunCoreD = clamp(log2(peak·K·Exposure·exposure·1.6 / 3), 0, 14.95)` — центр
  диска ~3 на экране, не плотнее сварочного стекла 10^-4.5 (`Sun.cpp:184-188`; применяется в `mesh.hlsl:151-164`).

### 6.4. Блик (`RenderSunGlare`, `sun.hlsl:255-309`)

Полноэкранный проход после собственного корабля. Вейлинг CIE (Stiles-Holladay / Vos 2003): на экране
`31.4 / (θ² + θ0²)` (θ в градусах), ресничная корона, лентикулярное гало ~2°. Видимая доля диска — 13 выборок глубины в
`VSG`; пропускание воздуха к Солнцу — `FxTransToSun` у камеры в `PSG` (только PS видит t8/b4). Фильтр визора над
Солнцем убирает блик (`sGlare.w`).

### 6.5. Взаимодействие с атмосферой

- Диск: пропускание прохода атмосферы `min(T·exp(fwd), 1)` по лучу (с delta-scaling прямого пика аэрозоля).
- Угловой радиус Солнца в b4 (`mGeo.w`) — `6.957e8 / dist` от центра планеты (`FxAtmo.cpp:136`), в `Sun.cpp` —
  `asin(oapiGetSize(hS) / dist)` от камеры.
- Экспозиция глаза (§6.6) входит в яркость на экране через `gHazeRGB.w`, а не в сами значения прохода.

### 6.6. Адаптация глаза (`Atmosphere::UpdateExposure`, `FxAtmo.cpp:376-419`)

- `E = LightAt(cp, sun, false)` — освещённость горизонтальной площадки у камеры (прямое Солнце × `max(mu, 0)` + небо),
  `En` — то же при Солнце в зените (местный полдень). Вне атмосферы — 1.
- `Y = lum(E)`, `Ynoon = lum(En)` (Rec.709); множитель облачности циклона `StormCameraLight()` и `g_stormLight` (§9).
- Цель: `target = clamp(1/Y, 1, max(1, 1.5/Ynoon))` — 1 под земным полуднем и в космосе; не выше местного полдня ×1.5,
  поэтому сумерки и ночь остаются тёмными, а под облаками Венеры глаз адаптируется к ~1 % дневного света.
- Цветовой баланс (фон Крис, `ADAPT_K = 0.55`): `w = En / Ynoon`, `gain = w^-0.55 / lum(w^0.45)`, каждый канал в
  `[0.05, 20]`.
- Сглаживание в лог-пространстве с постоянной 1.5 с реального времени.
- Выход: `g_fxAtmo.exposure`, `g_fxAtmo.white[3]`, `g_fxAtmo.light[3]` (= `E`; используется `Liquid.cpp:175`,
  `Lights.cpp:674`). В b0: `gHazeRGB.w = Exposure × exposure`, `gAdapt = (white, exposure)` (`Client.cpp:1238, 1247`);
  `LightsAdaptEye` (`Lights.cpp`) дополнительно учитывает свет фар и ламп. Тон-маппинг: `× gHazeRGB.w · gAdapt.rgb · 1.6`.

### 6.7. Ночь, сумерки, звёзды

- За терминатором прямой свет обнуляется `FxTransToSun` (сглаживание на угловом радиусе Солнца); небо и рассеянный
  свет продолжаются из таблиц MS и освещённости по `muS` до −1 (сумеречное небо, тень планеты в воздухе).
- Других источников ночного света (Луна, свечение неба) в модели нет (в коде не найдено). Заливка 0.02 на экране
  (`mesh.hlsl`) остаётся.
- Звёзды: `StarVisibility` (`FxAtmo.cpp:235-253`) — 200 шагов от камеры до верха:
  `vis = exp(-τ_зел) × (1 - day · min(30 · τ_sca,син, 1))`, `day = clamp((mu + 0.12)/0.17, 0, 1)` (небо светлое до ~7°
  под горизонтом).

## 9. Ограничения, замечания по коду, добавление планеты

### 9.1. Ограничения модели

- Три канала RGB, без спектрального интегрирования; без рефракции; без поляризации.
- Многократное рассеяние — изотропное приближение Hillaire; для толстых столбов — эвристическая двухпотоковая добавка.
- Земля — сфера радиуса `R` с постоянным альбедо; рельеф и текстуры в таблицы не входят.
- Освещённость `CSIrr` не включает отражение от земли (оно добавляется в `FxSkyLight` по альбедо).
- Атмосферная перспектива на объектах после прохода атмосферы (собственный корабль, частицы `particles.hlsl` —
  `ApplyHaze` при FX пустая) не применяется.
- Объём атмосферной перспективы — только для планеты камеры и только внутри её атмосферы; разрешение — 12×12 пикселей
  на столбец, 64 среза.
- Таблицы на планету — ~0.75 МБ видеопамяти (RGBA32F: 256×64 + 64×64 + 64×32 + 256×96) плюс CPU-копии пропускания и
  освещённости (~0.3 МБ); строятся для всех планет с атмосферой при
  первом кадре.
- Нет ночных источников света, кроме заливки.

### 9.2. Расхождения и подозрительные места

1. **Устаревшие размеры в комментариях.** `fx_atmo_lut.hlsl:4-5` — «CSMS 32x32», «CSIrr 64x16»;
   `fx_atmo_sky.hlsli:8` — «32 x 32»; `fx_atmo_light.hlsli:22` — «rows 64..79». Фактически `MS_N = 64` (64×64),
   `FX_IH = 32` (64×32, строки 64..95 в `lut` высотой 96, `FxAtmo.cpp:109`).
2. **Двойной учёт облачности циклона в экспозиции.** `FxAtmo.cpp:397` умножает `Y`, `Ynoon` на `StormCameraLight()`,
   затем `FxAtmo.cpp:400-401` — ещё раз на `g_stormLight`. Присваиваний `g_stormLight` в `src` нет (только объявление
   `= 1.0f`, `FxAtmo.cpp:380`), хотя комментарии (`FxAtmo.h:6-8`) говорят, что его задаёт `Storm.cpp`. Сейчас второй
   множитель равен 1; если его начнут задавать, ослабление применится дважды.
3. **`skypano.hlsl` не используется.** Ссылок на файл или `cbuffer Pano` в `src` нет; `liquid.hlsl` вызывает
   `FxSkyRadiance` попиксельно (`liquid.hlsl:338, 349`). По коду не ясно, оставлен ли он на будущее.

### 9.3. Добавление атмосферы планеты

1. Убедиться, что в Orbiter у планеты есть атмосфера (`oapiPlanetHasAtmosphere`; в `Config\<Planet>.cfg` — параметры
   `Atm*`). Без этого `.atmo.cfg` не читается.
2. Создать `Config\D3D11Client\<Planet>.atmo.cfg` (имя — как у тела в Orbiter). В шапке указать длины волн каналов и
   источники данных (как в существующих файлах).
3. Газ: `RayleighScatter` = земной Рэлей (`5.802e-6 13.558e-6 33.1e-6`) × (числовая плотность / земная у уровня моря)
   × (сечение газа / сечение воздуха); `RayleighH = kT/(mg)`. Если профиль температуры резко меняется — `RayleighBreak`,
   `RayleighH2`.
4. Аэрозоль: `MieExt` = вертикальная оптическая толща / `MieH` (для экспоненты); облачный слой — `MieLayer base top`,
   `MieExt` = толща / толщина слоя; `MieSSA`, `MieG` по каналам.
5. Поглотитель: `AbsorbExt` (в пике), `AbsorbCentre`, `AbsorbHalfWidth` (толща = `AbsorbExt × AbsorbHalfWidth`).
6. `Top` — где плотность пренебрежима (по умолчанию `12 × RayleighH`); `GroundAlbedo`.
7. Проверить журнал: строки `atmosphere <Planet>: …`, `… tables: …`, при толстых облаках — `opaque from above below`;
   сравнить пропускание к зениту с `exp(-τ)`, посчитанным вручную по значениям из файла.
8. Для режима без FX-атмосферы при необходимости — `Config\D3D11Client\<Planet>.cfg` с цветами старой системы (§4.5).
