# Облака

[← оглавление](DEVELOPER.md)

Состояние кода: 21.10.2026

Глава описывает все облачные системы клиента: объёмные слои (Титан), объёмный ураган Земли, а также файлы облаков Земли,
которые лежат в `src\` и `shaders\`, но не входят в сборку. Атмосфера (таблицы пропускания, свет неба, марш воздуха
`FxMarch`) описана в [atmosphere.md](atmosphere.md); дождь под ураганом (`StormRain.cpp`) — в [rain.md](rain.md).
Номера строк сверены с файлами на дату выше; при расхождении — поиск по имени функции.

| 2 | `RenderStormShadow` → `GpuSub(fi, 3)` | `Client.cpp:1013` | умножает освещённую сцену на пропускание урагана к Солнцу (до воздуха) |
| 3 | `FxRenderTransparent` → `GpuSub(fi, 4)` | `Client.cpp:1014-1015` | воздух (небо, воздушная перспектива) поверх сцены по глубине — [atmosphere.md](atmosphere.md) |

| 6 | `RenderClouds` → `GpuSub(fi, 6)` | `Client.cpp:1019-1020` | объёмные слои (Титан): марш на половинном разрешении и наложение |
| 7 | далее `LightsRenderAir`, `ExhaustRender`, частицы, `RenderRain`, `RenderStormRain`, … | `Client.cpp:1021-1029` | облака уже в `hdrRTV`; дождь урагана читает карту урагана |

Перед кадром `Orbiter` вызывает `clbkPreStep` → `StormPreStep` (`Client.h:594`, `Storm.cpp:640`): турбулентность для кораблей.
Свет у камеры под ураганом учитывается в адаптации глаза: `Atmosphere::UpdateExposure` вызывает `StormCameraLight()`
(`FxAtmo.cpp:397`).

Общее для обоих рисующих проходов:

- **Цель.** Итоговое наложение пишется в `hdrRTV` (R16G16B16A16_FLOAT, при MSAA — многовыборочная) без DSV.
- **Глубина.** Глубина сцены читается как текстура `depthSRV` (одновыборочная R32F после `ResolveDepth()`, `AA.cpp:94`);
  обратный Z: `z ≤ 1e-9` — небо (бесконечность). Расстояние до сцены восстанавливается через обратную матрицу VP:
  `length(mul(float4(ndc.xy, z, 1), InvVP).xyz / w)`.
- **Смешивание** (`Clouds.cpp:134-138`, `Storm.cpp:219-223`): `Src = ONE`, `Dest = SRC_ALPHA`, запись только RGB:
  `dest = dest · a + rgb`. Марш выдаёт предумноженный цвет `rgb = T_air · L_cloud + L_air · (1 − T_cloud)` и
  `a = T_cloud`: сцена за облаком (уже с воздухом) гасится пропусканием облака, воздух перед облаком добавляется заново
  для той доли, которую облако перекрыло.
- **Тень урагана** (`Storm.cpp:224`): `Src = ZERO`, `Dest = SRC_COLOR` — `dest = dest · k`.
- **Полноэкранные проходы** — треугольник из `SV_VertexID` (функция `VS` в каждом файле), без вершинных буферов.

## 3. Объёмные слои (Титан): `Clouds.cpp`, `clouds.hlsl`

### 3.1 Назначение

Слои облаков на сферических оболочках `[R + base, R + top]` вокруг тела, заданные строками `Layer` в `Clouds.cfg`.
Для каждого пикселя половинного разрешения — марш от камеры по лучу между оболочками до сцены, свет Солнца через
воздух и облако, свет неба, воздух перед облаком. Временного накопления нет.

### 3.2 Ресурсы

| Ресурс | Формат / размер | Создаётся | Обновление |
|---|---|---|---|
| `clNoise` (t0) | Texture3D 64³ R8G8B8A8_UNORM, IMMUTABLE, **1 мип** | `MakeNoise` (`Clouds.cpp:90-109`), CPU, один раз на устройство | никогда |
| `clTex` (RT0) | Texture2D `RW/2 × RH/2` R16G16B16A16_FLOAT | `RenderClouds` (`Clouds.cpp:144-154`) | каждый кадр |
| `clTexT` (RT1) | Texture2D `RW/2 × RH/2` R32_FLOAT — расстояние до облака `tc` | там же | каждый кадр |
| `clCB` (b1) | 21 × float4 = 336 байт, DYNAMIC | `Clouds.cpp:132` | `Map(DISCARD)` каждый кадр |

Все ресурсы пересоздаются при смене устройства (`clDev != dev`, `Clouds.cpp:121-124`); при смене размера окна — цели.

Шум (`MakeNoise`, по схеме Nubis, Schneider 2015):

- `pf` — сумма 4 октав периодического Перлина с периодами 4, 8, 16, 32 ячейки, веса 1, ½, ¼, ⅛, нормирована:
  `pf = Σ / Σw · 0.5 + 0.5`;
- `W(n)` — периодический Уорли F1, инвертированный: `1 − min(1, d_min)` (1 в зерне ячейки), `n` ячеек на тайл;
- `wf = 0.625 · W(4) + 0.25 · W(8) + 0.125 · W(16)`;
- канал r: `clamp(pf + (wf − 0.5) · 0.9, 0, 1)` (Перлин–Уорли); g: `W(8)`; b: `W(16)`; a: `W(32)`.

Генерация — 64³ вокселя на CPU в первом кадре над телом со слоями; время не измеряется и в журнал не пишется.

### 3.4 Плотность (`Density`, `clouds.hlsl:44-91`)

Для слоя `l` в точке `p` (радиус `r`):

1. Доля высоты `hf = (r − Rb) / (Rt − Rb)`; вне `(0, 1)` — 0.
2. Координаты шума вдоль кругов широт (полосы, вытянутые зональным ветром; комментарий ссылается на Cassini ISS PIA21450):
   `P` — точка в системе планеты, `lat = asin(P.y/|P|)`, `lon = atan2(P.z, P.x)`,
   `east = lon · Rb · cos(lat) − wind · t`,
   `pp = (east / 6, lat · Rb, (|P| − Rb) · 2) / scale`. Восток растянут в 6 раз, вертикаль сжата вдвое; полосы дрейфуют
   на восток со скоростью `wind`. Азимут ветра (`az`) в шейдере не используется — дрейф всегда вдоль восточного направления.
3. Погода (fBm на сфере): `wf = 0.6·N(0.11·pp) + 0.3·N(0.27·pp + 0.31) + 0.1·N(0.71·pp + 0.73)`, `N` — канал r шума;
   растяжение `wf = sat((wf − 0.5) · 3 + 0.5)` (без него шум у 0.5 ± 0.15 и покрытие 0.45 давало пустое небо, `clouds.hlsl:60-62`).
4. Покрытие в точке: `cover = sat(cover_cfg · 2 · wf)`; при `cover ≤ 0.01` — 0.
5. Вертикальный профиль:
   - `cumulus` (линза конвективных полос): `topH = 0.4 + 0.6·cover`, `prof = smoothstep(0, 0.15, hf) · sat((topH − hf) / (0.5·topH))`;
   - `deck`: `prof = smoothstep(0, 0.2, hf) · smoothstep(1, 0.55, hf)`.
6. Форма (Nubis): `s = tShape(0.5·pp, lod)`, `fbmW = 0.625 s.g + 0.25 s.b + 0.125 s.a`, `sr = sat((s.r − 0.5)·2.5 + 0.5)`,
   `shape = sat(Remap(sr, (1 − fbmW)·0.35, 1, 0, 1)) · prof`,
   `d = sat(Remap(shape, 1 − cover, 1, 0, 1) · 1.5)`.
7. Детали (только при `lod < 0.5`): `s2 = tShape(pp · (1.5, 4, 4) + 0.17)`, `det = 0.625 s2.g + 0.25 s2.b + 0.125 s2.a`,
   `d = sat(Remap(d, 0.45·det, 1, 0, 1))` — края «съедаются» в волокна.
8. Экстинкция `σ = d · extinction` [1/м]. `DensityAll` суммирует до 4 слоёв (`clouds.hlsl:93-99`).

`lod = sat(t / 60000) · 2`. Так как у текстуры один мип-уровень, `lod` влияет только на включение деталей (`lod < 0.5`,
т. е. ближе 15 км); выбор мипа фактически не происходит.

### 3.5 Марш (`PSMarch`, `clouds.hlsl:128-200`)

- **Луч.** `d` из `cInvVP`; начало — камера, центр планеты `mCentre.xyz` (b4, атмосфера).
- **Сцена.** Расстояние `sceneT` по **максимальной** из четырёх глубин полноразмерных пикселей под текселом (обратный Z:
  максимум = ближайшая) — облако не заходит на холм.
- **Отрезок** (`Shells`, `clouds.hlsl:102-124`): пересечение с оболочками `rmin = min(Rb)`, `rmax = max(Rt)`; три случая
  (камера ниже, внутри, выше слоёв); длина ограничена 150 км (`t1 = min(t1, t0 + 150000)`), затем `t1 = min(t1, sceneT)`.
  Камера внутри слоя — `t0 = 0`: пролёт сквозь облако работает тем же маршем.
- **Шаги.** `N = Steps` равных шагов `dt = (t1 − t0) / N`; смещение по пикселю и кадру — interleaved gradient noise
  `ign = frac(52.9829189 · frac(dot(pos + frame·(5.588, 7.123), (0.06711056, 0.00583715))))`.
- **На шаге** с `σ > 0`:
  - оптическая толщина к Солнцу: 4 пробы, длины 150, 300, 600, 1200 м, точки в серединах (`ls·(j + 0.5)`), `lod = 1.5`:
    `τS = Σ σ(p + sun·ls(j+0.5)) · ls`;
  - фаза: `ph = lerp(HG(0.8, cosθ), HG(−0.25, cosθ), 0.2)`, `HG(g, c) = (1 − g²) / (1 + g² − 2gc)^1.5` (относительно
    изотропной, т. е. без множителя 1/4π);
  - многократное рассеяние (октавы Wrenninge 2013 / Hillaire 2016, фаза высших октав сплющена к изотропной):
    `msS = ph·e^(−τS) + lerp(ph, 1, 0.7)·0.5·e^(−τS/4) + 0.25·e^(−τS/16)`;
  - Солнце: `FxSunLight(p)` (пропускание атмосферы до точки) или `SunLight(p)` без FX-атмосферы;
  - небо: `amb = FxSkyLight(up, p)·0.75 + FxSkyLight(−up, p)·0.25` (облучённость на высоте точки);
  - заслонение неба облаком сверху: `τU = σ(+250 м)·250 + σ(+900 м)·650 + σ(+2200 м)·1300`,
    `ambOcc = e^(−0.7 τU)·0.85 + 0.15`;
  - источник `S = sun·msS + amb·ambOcc`; альбедо однократного рассеяния принято 1 (жидкий метан, видимый диапазон);
  - шаг: `a = e^(−σ dt)`, `L += T·S·(1 − a)`, `T *= a`; выход при `T < 0.01`;
  - взвешенная глубина облака `tc = Σ T(1−a)t / Σ T(1−a)`.
- **Воздух перед облаком.** `FxMarch(org, d, …, tIn, tc, 16, La, Ta, fw)` только по участку внутри атмосферы
  (`tIn` — вход в верхнюю границу `mGeo.x`); `La *= π` (единицы радианса FX, см. [atmosphere.md](atmosphere.md)).
- **Выход:** `c = (Ta·L + La·(1 − T), T)`, `t = tc`. При `T > 0.999` — `(0, 0, 0, 1)`, `t = 1e9`.

### 3.6 Наложение (`PSComposite`, `clouds.hlsl:205-223`)

Полное разрешение. Пятиточечный «тент» по половинной текстуре (вес 0.4 в центре, 4 × 0.15 со смещениями ±(1, 0.5) и
±(0.5, 1) полноразмерных пикселя × 2) усредняет дизеринг шагов. `a > 0.999` — `discard`. Пиксель отбрасывается, если сцена
ближе `0.9 · tc` (корпус, холм перед облаком). `CloudDbg = 1` — вывод непрозрачности `1 − a` белым с компенсацией
экспозиции (`/ (gHazeRGB.w · gAdapt.rgb)`) и `a = 0` (сцена заменяется).

### 3.7 Цена

На пиксель половинного разрешения до `N` шагов; на каждом непустом шаге — `DensityAll` в точке (до 4 слоёв × 4–5 выборок
3D-шума), 4 пробы к Солнцу и 3 пробы вверх (`DensityAll` каждая) и вызовы `FxSunLight`/`FxSkyLight`. Время GPU выводится в
строке `GPU ms within: … clouds %.2f` (§8). Отдельных замеров в `Clouds.cpp` нет.

### 4.2 Положение и движение (`StateNow`)

- `MJD0 = 0` — центр стоит в `Lat/Lon` в начале **каждой** сессии: момент старта берётся заново, если MJD прыгнул назад,
  вперёд больше чем на сутки, или sim-время < 1 с при отличии MJD (`Storm.cpp:127-128`; клиент остаётся загруженным между
  сессиями).
- `t = (MJD − MJD0) · 86400` [с].
- Базис в точке старта через `oapiEquToLocal` (шаг 0.01°), центр после дрейфа — по большому кругу курса:
  `δ = clamp(Speed · t, −2·10⁶, 2·10⁶) / R`, `c = c0·cos δ + dir·sin δ`, `dir = n0·cos(Heading) + e0·sin(Heading)`.
  Дрейф ограничен 2000 км.
- В новом центре заново строятся единичные «восток» `S.e` и «север» `S.n` (система планеты), полушарие `S.hs = ±1`.

### 4.3 Погодная карта (`PSMap` / `StormMap`, `storm.hlsl:98-180`)

Texture2D 2048² R8G8B8A8_UNORM с полной цепочкой мипов (`Storm.cpp:210-215`). Проекция азимутальная равнопромежуточная
вокруг центра: `xy` (восток, север) [м], полуразмер `half = 1.1 · OuterKm` (`Storm.cpp:260`); при `OuterKm = 900` —
~0.97 км на тексель. Каналы:

| Канал | Смысл |
|---|---|
| r | покрытие низких/средних облаков 0…1 |
| g | высота верхней границы / `Top` |
| b | доля конвекции 0 (слоистые) … 1 (Cb) |
| a | щит перистых (central dense overcast) 0…1 |

Модель — аналитическая (рисунок по наблюдениям; комментарий `Storm.cfg` ссылается на NOAA P-3, Houze 2010). Обозначения:
`re = Eye`, `ww = Eyewall`, `rc = Canopy`, `ro = Outer` (м), `r = |xy| + 1`, `φ = atan2(y, x)·hs`, `ang = φ − bandAngle`.

- **Ветер вихря** (`VortexWind`): модифицированный вихрь Ранкина, `rm = re + 0.5·ww`, `vmax = 62 м/с` (константа в коде):
  `v = vmax·r/rm` при `r < rm`, иначе `v = vmax·(rm/r)^0.6`. Модель Холланда и профиль давления **не реализованы**.
- **Перенос мелких структур потоком:** две фазы `A`, `B` поворачивают координаты на `−ω(r)·tA,B·hs`, `ω = v/r`;
  `tA = (fa − 0.5)·Tc`, `tB = (fb − 0.5)·Tc`, `Tc = 1800 с`, фазы сдвинуты на `Tc/2`, вес `B` = `|2fa − 1|`
  (`Storm.cpp:269-271`). Шумы: `n` — fBm 6 октав на масштабе 40 км, `nc` — 5 октав на 9 км; `warp` — fBm на 180 км
  (неподвижен). `Fbm2` (`storm.hlsl:77-82`) — градиентный шум с поворотом каждой октавы, `0.5 + Σ/Σw · 0.9`.
- **Глаз и стена:** `eyeIn = 1 − smoothstep(0.85 re, 1.1 re, r)`; стена — гаусс
  `wall = exp(−((r − re − 0.45 ww) / (0.55 ww))²) · (0.8 + 0.4·Fbm2(...))`.
- **Спиральные полосы:** логарифмическая спираль с наклоном 17°: `k = 1/tan 17°`, `ψ = ang + k·ln(r / 50 км) + 2·warp`;
  `bandRaw = sat(0.5 + 0.5 cos 2ψ)^4`, второстепенная `band2 = sat(0.5 + 0.5 cos(3ψ + 1.3 + 3 warp))^8 · 0.5`;
  асимметрия `side = 0.75 + 0.35 cos(ang − 0.6)`; огибающая с неровным контуром `envB` (по `rE = r / fE(φ)`, хвост на
  юго-восток); за `0.8 rc` полосы разбиты на цепочки ячеек (`brk`).
- **Ров** вокруг стены (`moat`), **слоистый дождь** под щитом `strat`, **внешние кучевые** вдоль рукавов `outerCu`,
  редкие **Sc в глазу** `eyeCu`.
- **Покрытие:** `cov = sat(max(eyeCu, wallC, bandC, stratC, cuC))`.
- **Верхняя граница** — среднее по вкладам: стена `lerp(12500, Top, …)`, полосы 7000–14500 м, слоистые 5000–7500 м,
  кучевые 1500–4200 м, глаз 1800 м. **Конвекция** `conv = (wallC + 0.9 bandC + 0.8 cuC + 0.5 eyeCu) / Σ`.
- **Щит перистых:** диск с неровным краем `edge ≈ rc·(0.85 + …)`, волокна оттока по антициклонической спирали
  `ψO = ang − 0.9 k ln(r/50 км) + 1.5 warp`, `streak = (0.5 + 0.5 cos(23 ψO + …))^1.5 · Fbm2`; дыра над глазом шире наверху:
  `can *= smoothstep(1.3 re, 1.75 re, r)`.
- **Поворот рисунка полос** целиком: `bandAngle = 2π·t / (BandTurnHours·3600)` (`Storm.cpp:271`).

Обновление карты (`Prepare`, `Storm.cpp:334-338`): при ускорении времени > 1.5 — каждый кадр; иначе когда sim-время ушло
на ≥ 0.5 с или прошло 240 кадров; не чаще раза в кадр (сторож `oapiGetSysTime`). После отрисовки — `GenerateMips`, затем
мип 3 (256²) копируется в staging-текстуру; чтение на CPU — в следующих кадрах с `D3D11_MAP_FLAG_DO_NOT_WAIT`
(`Storm.cpp:325-333`). Эту копию (`cpuMap`) читают физика, экспозиция и дождь (`CpuMap`, билинейно).

### 4.4 3D-шумы (`storm_noise.hlsl`)

Создаются один раз вычислительными шейдерами (`Prepare`, `Storm.cpp:308-323`), затем `GenerateMips`; выборка — собственным
трилинейным сэмплером `sTri` (WRAP, `Storm.cpp:226-228`).

| Текстура | Размер | Тайл в мире | Каналы | Ядро |
|---|---|---|---|---|
| `sShape` (t0) | 128³ RGBA8, полный мип | `SHAPE_M = 9000 м` | r: Перлин–Уорли, g/b/a: Уорли 8/16/32 | `CSShape`, `Dispatch(32,32,32)`, `[numthreads(4,4,4)]` |
| `sDetail` (t1) | 32³ RGBA8, полный мип | `DETAIL_M = 1300 м` | r/g/b: Уорли 2/4/8, a = 1 | `CSDetail`, `Dispatch(8,8,8)` |

`CSShape`: `pf = sat(Σ_{o=0..3} 0.5^o·Perlin(p, 4·2^o) / Σw · 0.9 + 0.5)`, `wf = 0.625 W4 + 0.25 W8 + 0.125 W16`,
`pw = sat(Remap(pf, wf − 1, 1, 0, 1))`. Хэш — `Hash3` (LCG + перемешивание). Отличается от шума `Clouds.cpp` формулой
Перлин–Уорли и местом генерации (GPU). Шумы вынесены в отдельный файл, чтобы правка `storm.hlsl` не перекомпилировала их
(кеш шейдеров по исходнику).

### 4.5 Плотность (`Density`, `storm.hlsl:221-305`)

Вход: точка `P` (система планеты), доля деталей `detail`, мип карты `mapLod`, размер пикселя `foot` [м].

- `cells = sat(1.6 − foot/1500)` — вес 3D-ячеек; `shLod = clamp(log2(foot/70), 0, 6)` — мип шумов по размеру пикселя.
- `xy, h` — `MapXY` (азимутальная равнопромежуточная от центра, `storm.hlsl:187-198`); вне `h ∈ [−100, CanopyTop + 200]` — 0.
- **Наклон стены глаза («стадион»):** `eyeR = Eye·(1 + 0.9·sat(h/Top))`; `eyeCut = 1` ниже 2300 м, выше —
  `smoothstep(0.9 eyeR, 1.1 eyeR, r)`.
- **Низкий/средний ярус:** основание `base = Base + (g-шум на 7 км − 0.5)·300` (колебание ±150 м); верх
  `top = max(m.g·Top, base + 300)`, затем `top = base + (top − base)·lerp(lerp(0.75, 0.3, conv), 1, √cov)` (купола ниже по
  краям поля). Профили: конвективный `gC = smoothstep(0, 0.14, hf)·(1 − smoothstep(lerp(0.35, 0.7, cov), 1, hf))`,
  слоистый `gS = smoothstep(0, 0.2, hf)·smoothstep(1, 0.75, hf)`, `g = lerp(gS, gC, conv)`.
  Форма: `ShapeAt` (шум, перенесённый вихрем теми же двумя фазами, вертикальный масштаб `lerp(2.5, 0.8, conv)`),
  `bc = sat(Remap(sh.r, −(1 − wf)·lerp(0.25, 0.6, conv), 1, 0, 1))·g`,
  `d = sat(Remap(bc, 1 − cov, 1, 0, 1))·cov·smoothstep(0.22, 0.4, cov)`;
  издалека — переход к мягкому покрытию карты: `d = lerp(sat(1.3 cov − 0.15)·g, d, cells)`.
  Эрозия деталями (при `detail > 0.01`): `df` — fBm `tDetail(loc/1300 + (0, 0, 0.0005 t))`, `df = lerp(df, 1 − df, sat(4 hf))`,
  `d = sat(Remap(d, 0.55·df·detail·(1 − d), 1, 0, 1))` — только с краёв. Порог `d = sat((d − 0.08)/0.92)`.
  `σ += d · eyeCut · lerp(ExtStratiform, ExtConvective, conv)`.
- **Полосы дождя** под основанием сильных ячеек (`cov > 0.6`, `conv > 0.7`): `σ += rain · 6·10⁻⁵ · eyeCut · …`, альбедо 0.45.
- **Щит перистых:** основание `cb = CanopyBase + (CanopyTop − CanopyBase)·0.3·(1 − m.a)`, верх
  `ct = CanopyBase + (CanopyTop − CanopyBase)·(0.5 + 0.5 m.a)`; верх неровный: крупные вздутия `±1600 м` и пакеты гравитационных
  волн длиной 14 км, амплитудой 220 м к краю; профиль `g2 = smoothstep(0, 0.25, hc)·smoothstep(1, 0.55, hc)`, волокнистость
  `w = lerp(1, fib, 0.75)`; `d2 = sat(m.a^1.5·g2·w·0.9)·eyeCut`, `σ += d2·ExtCanopy`.

`DensityLo(P, detail) = Density(P, 0.5·detail, 1, 300).s` — дешёвая версия для проб света.

### 4.6 Свет

- **К Солнцу** (`SunTau`, `storm.hlsl:310-334`): 3–4 пробы `DensityLo`, первая длиной `60·(0.9 + 0.2·jit)` м, рост ×2.1;
  две длинные пробы (+2500 м × 3000 м, +7000 м × 6000 м) — тени башен друг на друга и на щит при низком Солнце; затем
  аналитическое пересечение щита: `τ += m.a·ExtCanopy·(CanopyTop − CanopyBase)·0.55/μS` (если точка ниже щита, `μS > 0.02`).
- **Фаза:** `ph0 = lerp(HG(0.8), HG(−0.3), 0.25)`, `ph1 = lerp(HG(0.4), HG(−0.15), 0.25)`.
- **Многократное рассеяние** (Wrenninge 2013) плюс диффузная составляющая по двухпотоковому приближению
  `1/(1 + 0.75 τ (1 − g))` с `g ≈ 0.85` → `0.11`:
  `msS = ph0·e^(−τS) + 0.5·ph1·e^(−τS/4) + 0.35/(1 + 0.11 τS)`.
- **Солнце и небо** берутся **один раз** в первой точке облака на луче: `sunC = FxSunLight`, `ambUp = FxSkyLight(up)`,
  `ambDn = FxSkyLight(−up)` (без FX: `SunLight`/`SkyLight`, `ambDn ×0.3`).
- **Заслонение неба:** `τU = DensityLo(+300 м)·300 + DensityLo(+1500 м)·1500` (пересчёт через шаг) плюс щит над точкой;
  `amb = ambUp·lerp(0.6, 1, hf)/(1 + 0.15 τU) + 0.6·ambDn`.
- **Источник и шаг:** `S = sunC·msS + amb`, `a = e^(−σ dt)`, `L += T·S·(1 − a)·alb` (энергосберегающий шаг, Hillaire 2016),
  выход при `T < 0.008`.

### 4.7 Марш (`PSMarch`, `storm.hlsl:382-492`)

- **Разрешение.** Цель `sTex` — `ceil(w/2) × ceil(h/2)` от половинного `w × h = RW/2 × RH/2`: каждый кадр считается один
  тексель из каждого блока 2×2 половинного изображения, по очереди `(0,0), (1,1), (1,0), (0,1)` (`sTmp.zw`, `Storm.cpp:283-284`).
- **Сцена.** Глубина берётся в собственном пикселе текселя (не максимум четырёх — иначе ореол тумана у близких силуэтов);
  во второй канал `t.y` пишется `sceneT` для совместной билатеральной сборки.
- **Отрезок** (`StormSpan`, `storm.hlsl:340-378`): оболочки от `R − 50` до `R + CanopyTop + 300` ∩ конус шапки шторма
  (`cos` половинного угла = `cos(1.12·Outer/R)`, `Storm.cpp:264`); длина ≤ 700 км; затем `min(t1, sceneT)`.
- **Шаги растут по лучу:** `t(u) = t0 + L·(e^(k u) − 1)/(e^k − 1)`, `u = (i + ign)/N`; `dtMin = max(12, 0.003·t0)`,
  `ρ = L/(N·dtMin)`; при `ρ > 2` `k` находится 6 итерациями `k = ln(1 + ρk)` (начало `ln ρ + 1`); иначе шаги равные.
  Смещение `ign` — хэш пикселя и кадра (не IGN: давал вертикальные полосы).
- **3D-детали** по расстоянию и размеру пикселя: `foot = 0.0015·t`, `detail = sat(1 − t/DetailKm)·sat(1.5 − foot/40)`,
  `fp = max(foot, dt/3)` (шум не мельче трети шага), мип карты `clamp(log2(2·fp / texel), 0, 6)`.
- **Длинный шаг** (`dt > 150 м`) в облаке: σ усредняется по трём точкам (`t`, `t ± 0.33 dt`).
- **Выход:** `c = (Ta·L + La·(1 − T), T)`; `t.x` — передняя граница облака (первая точка с `T < 0.97`) или средневзвешенная
  глубина; воздух перед облаком — `FxMarch` с 12 шагами (как в §3.5).

Переход «издалека 2D — вблизи 3D» в урагане не переключением, а весом: с орбиты пиксель крупнее 2.4 км — `cells = 0`,
форма облака задаётся только картой (мягкое покрытие); ближе 3D-ячейки шума включаются плавно; детали эрозии — ближе
`DetailKm` и при `foot < 60 м`.

Пролёт сквозь облако: камера внутри шапки → `t0 = 0`, первые шаги ~12 м; видимость внутри определяется `ExtConvective`
(0.025 1/м → ~120 м) и `ExtStratiform`.

### 4.8 Временное накопление (`PSTemporal`, `storm.hlsl:503-549`)

История — две пары целей половинного разрешения (ping-pong `hCur`): `hTex[i]` R16G16B16A16_FLOAT и `hTexT[i]` R32G32_FLOAT.

1. Для пикселя половинного разрешения: свежий ли он в этом кадре (`(q & 1) == sTmp.zw`); `c` — значение из четвертной цели,
   `cb` — её билинейная выборка.
2. Окрестность 3×3 четвертной цели: min/max, расширенные на `0.1·σ`.
3. Репроекция: точка облака `d·t` (система планеты) поворачивается назад вихрем на `ω(r)·Δt_sim·hs`
   (`sExt.x = clamp(Δt, 0, 600 с)`), переводится в глобальную систему прошлого кадра (`sPr0..2`: `Rp` прошлого кадра и
   центр планеты от прошлой камеры) и проецируется `sPrevVP`.
4. Клэмп истории — только пропорционально сдвигу на экране: `h = lerp(h0, clamp(h0, mn, mx), sat(0.7·mv))`, `mv` — сдвиг
   в текселях; стоя на месте история сходится полностью.
5. Свежий тексель: `lerp(h, c, lerp(0.2, 0.4, k))`, `k = sat(0.3·mv)`; остальные: `lerp(h, cb, 0.15·k)`.

История сбрасывается (`sTmp.x = 0`), если камера сместилась больше чем на 5 км за кадр (смена цели, скачок времени) или
пересозданы цели (`Storm.cpp:275`, `Storm.cpp:436`). `sTmp.y = 0.08` записывается, но шейдером не читается.

### 4.9 Наложение (`PSComposite`, `storm.hlsl:554-584`)

Полное разрешение; 4×4 текселя истории вокруг пикселя, вес «расширенного тента» `sat(1.5 − |x − f|·0.75)` по каждой оси,
умноженный на совпадение расстояний до сцены `exp(−12·|ln t.y − ln sceneT|)` (совместный билатеральный апсемплинг). Если
сумма весов < 1e-3 — берётся тексель с ближайшим расстоянием. `a > 0.999` — `discard`. Отладка `Debug = 1` — непрозрачность
белым (как в §3.6).

### 4.10 Тень (`PSShadow`, `storm.hlsl:588-628`)

Для каждого пикселя сцены (не неба) в пределах `1.05·Outer` и ниже `CanopyTop`, при `μS ≥ 0.01`:

- `τ` низкого яруса — 4 точки между `Base` и верхом колонны по лучу к Солнцу (`Density` с `detail = sat(1 − dist/40 км)`),
  каждая с весом `(top − Base)/4/μS`;
- `τC` щита — `m.a·ExtCanopy·(CanopyTop − CanopyBase)·0.55/μS` в точке пересечения луча со средней высотой щита;
- `Tsun = e^(−τA)`, `Tdif = 1/(1 + 0.11 τA)`, `skyT = 1/(1 + 0.11 τA μS)`, доля Солнца `k = lerp(0.8, 0.9, μS)`;
- множитель `f = k·(Tsun + 0.85·max(Tdif − Tsun, 0)) + (1 − k)·skyT` умножает сцену (`sBlendMul`). `Debug = 3` выводит `Tsun`.

Проход выполняется до воздуха, поэтому гасится только освещённая поверхность, не воздушная перспектива. Собственные карты
теней клиента (каскады) не меняются.

### 4.11 Свет у камеры и экспозиция (`StormCameraLight`, `Storm.cpp:663-689`)

Если камера ниже `CanopyTop + 500`: по копии карты
`τ = cov²·(ExtS + (ExtC − ExtS)·conv)·(top − max(h, Base))·0.35 + can·ExtCanopy·(CanopyTop − max(h, CanopyBase))·0.55`
(слагаемые — только если камера ниже соответствующего верха), цель `1/(1 + 0.11 τ)`, сглаживание `1 − e^(−dt/1.5 с)`.
Результат умножает освещённость, по которой `FxAtmo.cpp:397` выставляет экспозицию, и передаётся в дождь урагана
(`StormRain.cpp:152`).

### 4.12 Пролёт: турбулентность (`Physics`, `Storm.cpp:556-596`)

Работает при `Physics = 1` для каждого корабля, у которого `GetSurfaceRef()` — тело урагана, нет контакта с землёй и
высота ≤ `CanopyTop + 500`. Включение `Physics` меняет полёт кораблей (силы через `AddForce`).

- Интенсивность `I` (`Intensity`, `Storm.cpp:527-554`): в облаке `I = cov·(0.25 + 0.75 conv)·√sin(π hf)`, восходящий поток
  `w0 = 7·cov·conv·sin(π hf)` м/с; под основанием сильных ячеек (`cov > 0.3`, `conv > 0.5`) `I = 0.4 cov conv`,
  `w0 = −3 cov conv` (нисходящие потоки); в щите `+0.2·can`; всё × `eyeCut` (в глазу спокойно).
- Порыв — процесс Орнштейна–Уленбека по каждой оси (длина корреляции 250 м, как у модели Драйдена в конвективном облаке):
  `σ = Gust·13·I` м/с, `τ = 250/max(V, 20)` с, `a = min(dt/τ, 1)`, `g += −g·a + σ·√(2a)·N(0,1)` (вертикаль ×1.3).
- Сила `F = g_global·0.5·ρ·max(V, 5)·A`, `A = 0.6·size²`, ограничение `2·9.81·m`; приложена со смещением
  `clamp(side, −2, 2)·size·0.08` по оси x корабля (крен).
- Вызов: из `clbkPreStep`; если Orbiter его не вызывает 60 кадров — из кадра (`StormFrameFallback`); при паузе сила не
  копится (`lastSimT`). Шаг > 0.5 с — физика пропускается.

### 4.13 Дождь и ветер у камеры (`StormAt`, `Storm.cpp:709-751`)

Используется `StormRain.cpp` (при `Rain = 1`) и экспортом `StormSoundState` (модуль звука, вызывается всегда):

- интенсивность `mmh = cov²·(55 conv + 6 (1 − conv))·depth·eyeCut`, `depth = clamp((top − 2500)/5000, 0, 1)`;
- ветер — тот же вихрь Ранкина (`vmax = 62`, `rm = Eye + 0.5 Eyewall`), ×`clamp(0.8 + 0.2 h/2000, 0.8, 1)`, ниже 300 м над
  поверхностью — логарифмический профиль `ln(agl/z0)/ln(300/z0)`, `z0 = 0.03 м`, не меньше 0.3; приток к центру 20° ниже
  1500 м, выше 5°.

### 4.14 Цена и замеры

`RenderStorm` пишет GPU-время по своим таймстемпам (кольцо из 4 кадров, чтение с отставанием 3) и CPU-время (сглаживание
0.95/0.05) раз в 10 с (§8). Отметки: 0 — начало прохода тени, 1 — конец тени, 2 — начало марша, 3 — конец марша, 4 — конец
наложения. Компиляция восьми шейдеров идёт в `std::async` (холодный кеш занимал ~20 с); ураган появляется после её
окончания (`Storm.cpp:165-188`).

Память (по размерам ресурсов): шум формы 128³×4 Б ≈ 8 МБ (+ мипы), детали 128 КБ, карта 2048²×4 Б = 16 МБ (+ мипы ≈ 21 МБ),
staging 256 КБ; цели при 1920×1080: четвертная 480×270 (RGBA16F + RG32F), история 2 × 960×540 (RGBA16F + RG32F).

## 5. Код вне сборки: 2D-слой, облака Земли по слою, циклон

### 5.1 2D-слой (`CloudLayer.cpp`, `cloudlayer.hlsl`)

- Слой как у Orbiter: сфера радиусом `R + CloudAlt` (`OBJPRM_PLANET_CLOUDALT`, по умолчанию 7000 м), поворот
  `OBJPRM_PLANET_CLOUDROTATION`, глубина тени `1 − OBJPRM_PLANET_CLOUDSHADOWCOL` (по умолчанию 0.3); только при
  `OBJPRM_PLANET_HASCLOUDS` (`CloudLayer.cpp:77-108`).
- Покрытие — альфа тайлов DXT5 уровня 8 из `Textures\<тело>\Archive\Cloud.tree` (16 × 32 тайла по 512²), собранная в одну
  равнопромежуточную R8_UNORM 16384 × 8192 (~2.4 км/тексель) с мипами; альфа BC3 декодируется на CPU (`DecodeAlpha`).
  Тайлы читаются в главном потоке с бюджетом 3 мс на кадр; мипы — каждые 64 тайла и в конце (`CloudLayer.cpp:110-123`).
- `PSLayer`: пересечение луча со сферой, отсечение по глубине и по телу планеты, мип по размеру пикселя
  (`foot = t·pixelAngle / max(|d·up|, 0.08)`), освещение как у грунта: сверху `(sun·wrap + sky)·albedo`, снизу
  `(0.55·sun·sat(μ) + 0.8·sky)·(1 − 0.5a)·albedo`, `albedo = 0.75`; воздух перед слоем — `FxMarch`, 12 шагов.
- `PSShadow`: точка сцены → луч к Солнцу → покрытие на сфере слоя → множитель `1 − a·shadow`.
- Переход 2D ↔ 3D: `CloudLayerFade(alt) = clamp((alt − 3·10⁶)/10⁶, 0, 1)` — 2D-слой только с высоты > 3000 км, полностью —
  выше 4000 км; ниже — объёмные `EarthClouds` с долей `1 − fade`.
- Порядок по замыслу: `RenderCloudShadow` (тень + `CycloneUpdate`) до воздуха, `RenderCloudLayer` и `RenderEarthClouds` после.

### 5.2 Объёмные облака Земли по слою (`EarthClouds.cpp`, `earthclouds.hlsl`)

- Погода из покрытия слоя (`tCov`, мип 1) и, над циклоном, из карты `Cyclone` (`r` покрытие, `g` конвекция, `b` верх/16 км,
  `a` осадки/30 мм·ч⁻¹), смешение `e = sat((1.35 − 1.5|q|)/0.45)` (`earthclouds.hlsl:53-80`).
- Тип по колонне: лёд, если верх > 6.5 км без осадков (`ice`), основание слоистых 1200 → 500 м под дождём, конвективных
  1000 м, ледяных `top − 2200`; экстинкция `lerp(lerp(0.025, 0.05, conv), 0.0012, ice)`.
- Профили слоистый/конвективный/наковальня (если верх > 9 км), шум 6 км с дрейфом 8 м/с по оси x системы планеты,
  полосы дождя под основанием `2.2·10⁻⁴·pr^0.65`.
- Марш: оболочки `[R, R + 16500]`, шаг `clamp(0.012 t, 40, 900)` м (×4 в пустых колонках), не меньше `(t1 − t0)/N`,
  `N = EarthCloudSteps` (по умолчанию 96, 16…256); свет — 4 пробы к Солнцу (рост ×2.2), фаза
  `lerp(HG(0.85), HG(−0.2), 0.25)`, те же октавы, что в §3.5.
- Ключи `EarthCloudSteps` и `CloudDbg` читаются из `Client.cfg` при первой инициализации.

### 5.3 Циклон (`Cyclone.cpp`, `cyclone.hlsl`)

- `Cyclone.cfg`: строки `Cyclone = <body> <extratropical|tropical> <lat°> <lng°> <MJD0> <speed м/с> <heading°> <radius км>
  <stage 0..1> <stage/сутки> <vmax м/с> <r max wind км>` (`Cyclone.cpp:25-43`).
- Центр движется по большому кругу (`Travel`), стадия `stage0 + rate·(MJD − MJD0)` (0 волна … 1 окклюзия).
- Карта 512² R16G16B16A16_FLOAT **каждый кадр** на квадрат полуразмером `1.5·radius`; каналы: r покрытие, g конвекция,
  b верх/16 км, a осадки/30.
- Внетропический (норвежская модель, окклюзия Шапиро–Кейзера, конвейеры Карлсона/Браунинга): холодный фронт (узкая линия
  Cb ~55 км, ливни до 25 мм/ч), тёплый фронт со щитом до ~900 км (Ns → As → Cs, верх 4 → 9.5 км), голова запятой
  (логарифмическая спираль 18°), сухой клин, тёплый сектор (Sc), открытые ячейки Cu в холодном воздухе.
- Тропический: глаз `0.6·rmax`, стена, две спиральные полосы 15°, CDO, осадки `60·wall + 15·bands`.
- Перенос мелких структур вихрем Ранкина `v = vmax·r/rmax` / `vmax·(rmax/r)^0.6`, две фазы по 4 ч.

### 5.4 Подключение (если потребуется)

1. Добавить `src\CloudLayer.cpp src\EarthClouds.cpp src\Cyclone.cpp` в строку `cl` в `build.bat`.
2. В `clbkRenderScene` вызвать `RenderCloudShadow` до `FxRenderTransparent` и `RenderCloudLayer`, `RenderEarthClouds` после.
3. Проверить взаимодействие с ураганом: обе системы рисуют облака Земли и не согласованы (ураган не читает слой и наоборот).

## 6. Связь с атмосферой

Все проходы перед рисованием вызывают `FxBindLight(this)` (`Fx.cpp:72` → `Atmosphere::BindLight`, `FxAtmo.cpp:342`):

Подробности — [atmosphere.md](atmosphere.md). Геометрия облаков опирается на `mCentre` из b4: это центр той планеты, которую

## 8. Конфигурация

Все файлы читаются **один раз за загрузку DLL** (флаг `cfgRead` не сбрасывается); клиент остаётся загруженным между
сессиями, поэтому изменения требуют перезапуска Orbiter. Комментарий `Storm.cfg` «Read once per session» коду не
соответствует. Правка установленного `.hlsl` (в `Modules\D3D11Client\`) вступает в силу при следующем создании устройства
(новая сессия). Ключи после `;` — комментарии (`Storm.cfg`, `Cyclone.cfg`); `Clouds.cfg` читается `sscanf` по шаблону,
комментарием фактически является любая строка, не подходящая под шаблон.

4. Пролёт — строки `enters/leaves the cloud`.

## 10. Ограничения, замечания, подозрительное

- **2D-слоя облаков Земли нет** в сборке (§1, §5). Вне шапки урагана Земля без облаков; теней облаков Orbiter нет.
- **Ураган и Титан — отдельные системы** с разным шумом, разной формулой Перлин–Уорли и без общего кода.
- **Титан, временное накопление отсутствует**: дизеринг меняется каждый кадр (`frame mod 64`), сглаживается только
  пятиточечным фильтром — мерцание на краях возможно.
- **Титан, мипы шума.** У `clNoise` один уровень (`Clouds.cpp:105`), поэтому параметр `lod` в `SampleLevel` ничего не
  выбирает; на расстоянии возможно зерно (в `Storm.cpp:203` тот же эффект описан как «sand» и исправлен мипами).
- **Титан, ветер.** Азимут ветра и `cLay[3i+2]` не используются шейдером; дрейф всегда на восток. `cLay[3i+1].x = 0.85` не
  читается.
- **Титан, шов на 180° долготы.** Координата `east = lon·Rb·cos(lat)` скачком меняется при переходе `atan2` через ±π, а длина
  круга широты не кратна тайлу шума — по коду возможен разрыв рисунка вдоль меридиана 180° системы планеты и сжатие
  рисунка у полюсов. Запуском не проверялось.
- **Титан, комментарии.** В `clouds.hlsl:159` написано «6 steps, growing», в коде 4 пробы. В `Clouds.cpp:14` сказано, что
  `CloudDbg` читается из `Clouds.cfg` или `Client.cfg`; читается только из `Client.cfg`.
- **Ураган: модель ветра** — модифицированный вихрь Ранкина с `vmax = 62 м/с` и показателем 0.6, жёстко в коде
  (`storm.hlsl:100`, `Storm.cpp:731`); ключа для силы ветра нет; модель Холланда, профиль давления, эволюция (стадии) не
  реализованы. Рисунок — аналитический, не симуляция.
- **Ураган: `Debug = 2`** упомянут в `Storm.cpp:30`, но ни одна ветка шейдера его не обрабатывает.
- **Ураган: `sTmp.y = 0.08`** не читается (`PSTemporal` использует свои веса).
- **Ураган: свет один раз на луч.** `sunC`, `ambUp`, `ambDn` берутся в первой точке облака — для длинных лучей (вид с орбиты
  вдоль терминатора) различие освещения вдоль луча не учитывается.
- **Ураган сбрасывает регистр t7.** В конце `RenderStorm` вызывается `PSSetShaderResources(0, 8, nul)` (`Storm.cpp:483`),
  что снимает и карту теней клиента в t7 (`common.hlsli:28`). Повторно t7 привязывается только перед собственным кораблём
  (`Client.cpp:1038`) и в `VisorDrops.cpp`. Проходы между ними, читающие `ShadowAt` (`particles_gpu.hlsl`, `rain.hlsl`,
  `spray.hlsl`), при активном урагане получают пустую карту теней; `SampleCmp` по пустому ресурсу даёт 0, т. е. по коду их
  солнечный свет будет полностью в тени. Запуском не проверялось.
- **`g_stormLight`** (`FxAtmo.cpp:380`) нигде не присваивается и всегда равен 1; действующая связь с экспозицией — прямой
  вызов `StormCameraLight()` в `FxAtmo.cpp:397`.
- **Ураган: значения по умолчанию** в `struct Cfg` отличаются от `Storm.cfg` (`Top`, `CanopyBase/Top`, `ExtCanopy`, `Steps`,
  `Rain`, `Lat/Lon`) — при удалении ключа поведение меняется.
- **Ураган: дождь.** В коде по умолчанию выключен (комментарий: до переделки по образцу), в `Storm.cfg` сейчас `Rain = 1`.
- **Ураган: геометрия** зависит от `mCentre` из буфера атмосферы (§6).
- **Ураган: длина дрейфа** ограничена 2000 км; при больших `Speed·t` центр останавливается.
- **Один ураган на всё** (`struct Cfg C`), на одном теле.
- **`Physics` изменяет полёт** (силы на корабли); при `Gust = 0` порывы исчезают, но восходящий поток `w0` остаётся.

## 11. Как добавить облака другому телу

**Слои (`Clouds.cpp`).** Добавить строки `Layer = <имя тела> …` в `Clouds.cfg` (до 4 на тело; имя — как у
`oapiGetObjectName`). Требования: у тела должна работать FX-атмосфера (иначе свет — из простых цветов `SunLight`/`SkyLight`,
а `mCentre` по коду не ясен, §6). Подбор: `extinction` × толщина слоя ≈ вертикальная оптическая толщина при `cover = 1`;
`feature size` — масштаб рисунка по меридиану (по востоку — ×6, по вертикали — ½); `Steps` общий для всех тел. Перезапуск
Orbiter обязателен. Рисунок вытянут по широте (заложено для Титана, `clouds.hlsl:49-56`); для другого характера облаков
нужна правка `Density` (коэффициенты 6 и 2 в `pp`).

**Ураган (`Storm.cpp`).** `Body` в `Storm.cfg` можно поменять на любое тело; модель рассчитана на земной ураган (ветер 62 м/с,
высоты, экстинкции воды). Второй шторм одновременно не поддерживается.

**2D-слой из `Cloud.tree`.** Только через подключение кода вне сборки (§5.4).
