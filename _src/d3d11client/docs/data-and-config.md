# Данные и настройки

[← оглавление](DEVELOPER.md)

Все пути — относительно корня Orbiter (рабочая папка процесса).

## 1. `Config\D3D11Client\Client.cfg` — настройки клиента

Читается в `clbkInitialise` (`ClientCfg::Load`, `VideoTab.cpp:11-32`), пишется кнопкой OK диалога
Launchpad → Video → **Advanced** (`ClientCfg::Save`, `VideoTab.cpp:34-50`; диалог `IDD_ADVANCED` в `D3D11Client.rc`,
`AdvProc` `VideoTab.cpp:181-215`). Формат: `Ключ = число`, комментарий после `;`, ключ — только латинские буквы.

| Ключ | Поле | По умолчанию | Диапазон (диалог) | Где действует |
|---|---|---|---|---|
| `LodBias` | `lodBias` | 0 | −2…+2 | порог разбиения тайла `600·2^(−LodBias)` пикселей, каждый кадр (`Planet.cpp:351`) |
| `Anisotropy` | `aniso` | 16 | 1…16 | сэмплеры `s0`/`s1` — **только при создании устройства** (`Client.cpp:143`) |
| `Haze` | `haze` | 1 | 0…5 | множитель экстинкции дымки и видимости звёзд, каждый кадр (`Client.cpp:751, 754`) |
| `Exposure` | `exposure` | 1 | 0.2…5 | тон-маппинг (`gHazeRGB.w`, `post.hlsl:13`) |
| `Liquids` | `liquids` | 1 | 0/1 | проход жидкости (`Liquid.cpp`, `RenderLiquid`) |
| `Shadows` | `shadows` | 1 | 0/1 | проход теней (`Client.cpp:779`) |
| `StatsLog` | `statsLog` | 1 | 0/1 | строка `fps … GPU ms …` раз в 10 с (`Client.cpp:639`) |
| `AntiAliasing` | `aa` | 2 | 0 выкл., 1/2/3 MSAA 2/4/8×, 4 FXAA, 5 TAA (выпадающий список) | цели сцены и проходы сглаживания — **только при создании окна** (`AA.cpp`); при чтении ограничивается 0…5 |
| `RenderScale` | `renderScale` | 1 | 0.5…1 (поле «TAA render scale, %», 50…100) | только для TAA: сцена рендерится в `RW×RH` меньше окна и масштабируется TAAU — ⚠ добавлено сессией сглаживания во время написания, при следующем запуске |

Значения из файла при чтении **не ограничиваются** диапазонами (ограничивает только диалог; `aniso` дополнительно
`clamp(1,16)` при создании сэмплера).

Видео-параметры Orbiter (`VIDEODATA`): `deviceidx` (адаптер DXGI; по умолчанию — с наибольшей видеопамятью), `modeidx`,
`fullscreen` (= окно без рамки на весь основной монитор), `novsync`, `winw/winh` (меньше 800×600 → рабочая область
рабочего стола) — `VideoTab.cpp:94-163`. ⚠ `deviceidx` пока **не используется** при создании устройства:
`D3D11CreateDevice(nullptr, …)` берёт адаптер по умолчанию (`Client.cpp:95`).

## 2. `Config\D3D11Client\<Планета>.cfg` — атмосфера и жидкость

Читается в конструкторе `Planet` (`Planet.cpp:71-127`). Формат: `Ключ = a [b c]`, комментарий после `;`.
Векторный ключ с одним числом даёт `(a, a, a)`. Цвета — **линейные** (не гамма).

**Атмосфера** (только если `oapiPlanetHasAtmosphere`; ключ — буквы и цифры, без `_`):

| Ключ | Поле `AtmCfg` | Если ключа нет | Где используется |
|---|---|---|---|
| `SkyHorizon` r g b | `horizon` | `OBJPRM_PLANET_HAZECOLOUR`^2.2 (или 0.6 0.7 0.9) | цвет неба у горизонта, свет дымки (`gSky0`) |
| `SkyZenith` r g b | `zenith` | `0.45 × horizon` | цвет зенита (`gSky1`) |
| `Ambient` r g b | `ambient` | `0.4 × horizon` | свет неба на поверхностях (`gAmb`) |
| `Sun` r g b | `sun` | 1 1 1 | цвет прямого Солнца под атмосферой (`gSun`) |
| `HazeRGB` r g b | `hazeRGB` | 1 1 1 | спектральные веса экстинкции |
| `HazeExt` | `hazeExt` [1/м] | `6.5e-5 · rho0 / 1.2` (Земля: видимость ~60 км) | экстинкция у поверхности (`gAmb.w`) |
| `ScaleHeight` | `scaleH` [м] | `p0 / (rho0 · g)` из `ATMCONST` | высота однородной дымки, угасание неба с высотой |
| `Top` | `top` [м] | `ATMCONST::altlimit` или `10 · scaleH` | выше — камера «не в атмосфере» (нет неба/дымки) |

**Жидкость** (читается всегда; префикс `Liquid` — здесь, `AtmoFX_Liquid` — в `Config\GC`, см. ниже):

| Ключ (суффикс) | Поле `LiquidCfg` | По умолчанию | Смысл |
|---|---|---|---|
| `…Level` | `level` [м], **включает жидкость** | — | уровень над средним радиусом |
| `…Ext` | `ext` [1/м] | 0.3 | экстинкция |
| `…Index` | `index` | 1.29 | показатель преломления (F0 Френеля) |
| `…Color` / `…Colour` r g b | `colour` | 0.40 0.30 0.14 | цвет рассеянного в жидкости света |
| `…Weights` r g b | `wts` | 0.6 1.0 1.8 | спектральные веса экстинкции |

**Атмосфера снаружи** (эффект `FxAtmo.cpp`, читает тот же файл; кроме `HazeExt`, `HazeRGB`, `ScaleHeight`, `Top`, `Sun`):

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `HazeH` [м] | `ScaleHeight` | высота однородной дымки оболочки |
| `HazeSSA` r g b | оценка по цвету горизонта (`0.95·horizon/max`, 0.3…0.99) | альбедо однократного рассеяния |
| `HazeG` | 0.3 | асимметрия Хеньи–Гринстейна |

Пример — установленный `Config\D3D11Client\Titan.cfg` (с обоснованием значений в комментариях: Huygens DISR / Cassini).

## 3. `Config\GC\<Планета>.atm.cfg` — ключи AtmoFX, которые читаем

Только жидкость: `AtmoFX_LiquidLevel`, `AtmoFX_LiquidExt`, `AtmoFX_LiquidIndex`, `AtmoFX_LiquidColor`/`AtmoFX_LiquidColour`,
`AtmoFX_LiquidWeights` (`Planet.cpp:107-127`). Файл читается первым, затем `Config\D3D11Client\<Планета>.cfg` может
переопределить. Ключ `AtmoFX_Liquid` без суффикса пропускается. Остальные ключи AtmoFX (цвета неба, облака, …) **не
читаются**: они подобраны в гамма-пространстве D3D9-клиента, наши линейные значения — в `Config\D3D11Client`.

## 4. Тайлы планет

Дерево Orbiter: уровень 4 — два корневых тайла (запад: долгота −π…0, `ilng=0`; восток: 0…π, `ilng=1`),
каждый следующий уровень делит тайл на 4. `ilat` растёт **к югу** (`Planet.cpp:179`); ребёнок `k`: бит 1 — южная
половина, бит 0 — восточная. Максимальный уровень — `OBJPRM_PLANET_SURFACEMAXLEVEL`, ограниченный 4…21 (иначе 18)
(`Planet.cpp:63-64`).

**Источники** (для каждого тайла: сначала отдельный файл, потом архив):

| Слой | Отдельные файлы | Архив |
|---|---|---|
| Текстура | `Textures\<Планета>\Surf\<lvl:02>\<ilat:06>\<ilng:06>.dds` | `Textures\<Планета>\Archive\Surf.tree` |
| Высоты | `Textures\<Планета>\Elev\<lvl:02>\<ilat:06>\<ilng:06>.elv` | `Textures\<Планета>\Archive\Elev.tree` |

`LoosePath` — `Planet.cpp:151-156`. Существование файлов кешируется (`fileCache`). Слои `Mask`, `Cloud`, `Label`,
`Elev_mod` **не используются**.

Тайл без собственной текстуры рисуется подпрямоугольником текстуры ближайшего предка (`Planet.cpp:374-383`); без
собственных высот — интерполяцией четверти высот родителя (`Planet.cpp:214-230`). Разбиение идёт, только если хотя бы у
одного ребёнка есть свои данные (текстура или высоты) (`Planet.cpp:352-359`).

### `.tree` (TOC-архив, `TreeArchive`, `Planet.cpp:11-52`)

```
смещение  тип       поле
0         DWORD     сигнатура 'T','X',1,0   (проверяется)
4         DWORD     размер заголовка = 48    (проверяется)
8         DWORD     ? (не читается)
12        DWORD     смещение начала данных (dataOfs)
16        INT64     длина данных (dataLen)
24        DWORD     число узлов N
28        DWORD×3   корни уровней 1, 2, 3
40        DWORD×2   корни уровня 4: запад, восток
48        N × 32 байта: INT64 pos; DWORD size (распакованный); DWORD child[4]  (−1 = нет)
```
Индекс узла: уровни 1–3 — свой корень; уровень 4 — `root[3 + (ilng & 1)]`; глубже — `child[((ilat&1)<<1)|(ilng&1)]`
родителя (`Planet.cpp:31-38`). `size == 0` — узел без данных. Сжатый размер = `pos` следующего узла − `pos` (т.е. код
предполагает, что узлы лежат в файле по порядку), последний — до `dataLen`. Распаковка — `oapiInflate`.

### `.elv` (`ParseElev`, `Planet.cpp:185-198`)

```
0   char[4]  "ELE\x01"
4   int      размер заголовка (данные начинаются с него)
8   int      тип: -16 = INT16, 8 = UINT8, иное = плоский тайл (все значения = offset)
28  double   scale
36  double   offset          высота [м] = sample · scale + offset
данные: 259 × 259 отсчётов, строка 0 — юг, с рамкой в один отсчёт вокруг 257 × 257
```
Поля между 12 и 28 (размеры сетки, поля) и после 44 (границы тайла) не читаются — размер 259 зашит в код.

Сетка тайла: 65 × 65 узлов — каждый 4-й отсчёт (`1 + 4i`), плюс «юбки» по 4 краям, опущенные на
`0.02·(размер тайла) + 20 м` (`Planet.cpp:233-280`); общий индексный буфер на все тайлы (`Client.cpp:178-197`).
Нормали — по соседним узлам (с заходом в рамку). Позиции вершин — float относительно центра тайла.

## 5. Каталог звёзд

`Config\CSphere\Data\star.bin` читается не нами напрямую, а через `oapi::CelestialSphere::LoadStars()`
(`CelSphereAPI.h:111`, защищённый метод; обёртка `StarLoader` — `Stars.cpp:6-13`). Отбор по яркости и цвета — по
пользовательским настройкам Orbiter внутри `Orbiter.lib`. Записи `StarRenderRec {pos (единичный вектор), col, brightness}`
кладутся в структурированный буфер по 32 байта (`Stars.cpp:17-34`); в прогоне 19.10 — 41 057 звёзд. Созвездия, подписи,
фоновое изображение неба (`Config\CSphere\bkgimage.cfg`) не используются.

## 6. Текстуры (DDS)

`Dds.cpp`: DXT1/DXT2-3/DXT4-5 → BC1/BC2/BC3, ATI1/BC4U, ATI2/BC5U, `DX10`-заголовок (формат как есть); несжатые 32/24 бит,
16 бит по маскам (A4R4G4B4, R5G6B5, A1R5G5B5…), 8 бит (luminance или по маске). Цветные форматы создаются в **sRGB**-варианте
(`ToSRGB`), т.е. все текстуры мешей и тайлов считаются гамма-кодированными. Сжатые — mip-цепочка из файла (до первого
неполного уровня), несжатые — mip-цепочка строится на CPU боксом 2×2. Сжатые с размером, не кратным 4 (и ≥ 4), не грузятся.
Порядок поиска текстур мешей: `Textures2\`, `Textures\`, путь как есть (`Client.cpp:348-352`); отсутствие — строка
`texture not loaded: …` в логе.
