## 1. `Config\D3D11Client\Client.cfg`

### 1.1. Формат, чтение, запись

Файл читают несколько независимых читателей; общего разборщика нет.

| Читатель | Что читает | Когда |
|---|---|---|
| `ClientCfg::Load` (`VideoTab.cpp:11-44`) | основные ключи (§1.2) в `g_cfg` (`Client.h:42-66`) | один раз за процесс: `clbkInitialise` (`Client.cpp:76`), при старте Orbiter |
| `LoadCfg` в `Lights.cpp:25-44` | ключи локальных источников света (§1.3) | при первом `LightsFrame` (`Lights.cpp:104`), один раз за процесс |
| `LoadCfg` в `VisorDrops.cpp:32-56` | ключи капель на визоре (§1.3) | при первом обращении (`VisorDrops.cpp:185, 257, 355`), один раз за процесс |
| `RainRate` (`Rain.cpp:25-44`), `RainAt` (`VisorDrops.cpp:62-78`) | `Rain`, `RainArea` после `Fx.cfg` | при первом обращении, один раз за процесс |
| `ReadCfg` в `Clouds.cpp:27-51` | `CloudCfg`, `CloudDbg` | при первом кадре облаков, один раз за процесс |
| `Liquid.cpp:283-290` | `LiqDbg` | при первом кадре жидкости, один раз за процесс |
| `FxTestKey` / `FxTestNum` / `FxTestShotTime` (`FxTest.cpp:19-51`) | тестовые и диагностические ключи (§1.4) | при каждом вызове файл читается целиком; вызывающие кешируют значение в `static` |

Формат:

- `ClientCfg::Load`, `Lights.cpp`, `VisorDrops.cpp`: строка `Ключ = число`; всё после `;` отбрасывается; шаблон
  `" %63[A-Za-z] = %lf"` — ключ только из латинских букв (цифры и `_` не допускаются), регистр значим.
- `FxTestKey`: поиск ключа в начале строки без учёта регистра (`_strnicmp`), затем пробелы и `=`; значение — остаток
  строки до `;`; при нескольких строках с одним ключом действует последняя. Отсутствие ключа = 0 (`FxTestNum`) или −1
  (`FxTestShotTime`).
- `Rain.cpp`, `Clouds.cpp`, `Liquid.cpp`: `sscanf` по фиксированному шаблону (`" Rain = %lf"`, `" CloudCfg = %95s"`, …).

Запись: кнопка OK диалога Launchpad → Video → **Advanced** (`AdvProc`, `VideoTab.cpp:205-245`; диалог `IDD_ADVANCED`
в `D3D11Client.rc`) вызывает `ClientCfg::Save` (`VideoTab.cpp:46-74`). `Save` **перезаписывает файл целиком** и пишет
только 21 ключ `ClientCfg` в фиксированном порядке с комментариями. Все остальные ключи (§1.3, §1.4) при этом из файла
удаляются.

Диалог меняет `g_cfg` в памяти сразу; файл перечитывается только при следующем старте Orbiter. Поскольку диалог
доступен только в Launchpad (между запусками симуляции), для ключей, читаемых каждый кадр, и для ключей, читаемых при
создании окна, изменение через диалог действует со следующего запуска симуляции. Правка файла вручную действует со
следующего старта Orbiter.

`tools\run_test.ps1` на время прогона дописывает ключи в этот файл (`-AA`, `-Set`) и затем восстанавливает его —
см. [build-and-test.md §3](build-and-test.md#3-тестовый-прогон--toolsrun_testps1).

Обозначения в столбце «Когда действует»: **кадр** — значение читается из `g_cfg` при каждом кадре; **окно** — при
создании устройства и окна рендера (`CreateDevice`, `Client.cpp:308-458`, вызывается из `clbkCreateRenderWindow` при
каждом запуске симуляции); **процесс** — модуль читает ключ один раз за время жизни процесса.

## 5. Микротекстуры и материал грунта

### 5.1. `Config\MicroTex.cfg` (формат D3D9Client, только чтение)

Блоки `BODY <имя>`, `NORMALS 0|1`, `LEVEL 0..2 <текстура в Textures\> <пикселей на метр>`; комментарии `//`
(`Planet.cpp:135-151`). Блок принимается, если заданы все три уровня (`micCfg`). Текстуры грузятся отдельным потоком
(`Planet::MicroLoad`, `Planet.cpp:297-315`), когда камера впервые опускается ниже 100 км и `MicroTextures = 1`
(`Planet.cpp:779-780`): `NORMALS 1` — линейно (нормаль в `.a/.g`, яркость в `.b`), `NORMALS 0` — sRGB. Период повтора
уровня = ширина текстуры / разрешение (м). Средний тексел уровня считается на CPU из мипа ≤ 64² (BC1/BC3, `DdsMean`,
`Planet.cpp:164-225`); шейдер берёт деталь относительно него. Каждый уровень гаснет там, где его тексел меньше 1/16
пикселя, самый грубый — не дальше 25 км (`Planet.cpp:781-786`). Строки журнала:
`planet <имя>: micro texture <файл>, <px> px, repeats every <м> m, mean …` и `… micro texture <путь> not loaded`.

### 5.2. Материал грунта (`GroundDetail`)

Загружается один раз, когда камера впервые ниже 30 км (`Planet.cpp:788-797`):

- `Textures\<Планета>_ground_cobbles.dds`, `Textures\<Планета>_ground_sand.dds` — DDS с заголовком DX10,
  `R16G16B16A16_UNORM` или `R8G8B8A8_UNORM`, с сохранённой mip-цепочкой (`LoadHeight16`, `Planet.cpp:227-249`). Нужны
  оба, иначе материал выключен (`gmatState = 3`).
- `Config\OrbiterCrew\Ground\<Планета>.cfg`: ключи `CenterLat`, `CenterLon` [°], `StepM` [м], `W`, `H` [ячеек];
  `<Планета>.bin`: по байту на ячейку, строки с севера на юг, столбцы с запада на восток; классы 1, 2, 3 → каналы g, b, a,
  иначе r (`Planet::LoadGround`, `Planet.cpp:254-295`). Строка журнала: `planet <имя>: ground classes WxH cells of … m …`.

Материал рисуется на тайлах ближе 40 м к камере (`Planet.cpp:937`), повтор 10.24 м.

## 6. Тайлы планет

### 6.1. Дерево

Уровень 4 — два корневых тайла (запад: долгота −π…0, `ilng = 0`; восток: 0…π, `ilng = 1`); каждый следующий уровень
делит тайл на 4 (`Planet::Child`, `Planet.cpp:353-366`). `ilat` растёт к югу; ребёнок `k`: бит 1 — южная половина,
бит 0 — восточная. Максимальный уровень — `OBJPRM_PLANET_SURFACEMAXLEVEL`, ограниченный 4…21 (без параметра — 18,
`Client.h:324`; `Planet.cpp:69-70`).

### 6.2. Источники

Для каждого тайла: сначала отдельный файл, затем архив. Существование файлов кешируется (`Planet::FileExists`,
`Planet.cpp:324-332`). Путь отдельного файла — `LoosePath` (`Planet.cpp:334-339`).

| Слой | Отдельные файлы | Архив | Когда |
|---|---|---|---|
| Текстура | `Textures\<Планета>\Surf\<lvl:02>\<ilat:06>\<ilng:06>.dds` | `Textures\<Планета>\Archive\Surf.tree` | всегда |
| Высоты | `Textures\<Планета>\Elev\<lvl:02>\<ilat:06>\<ilng:06>.elv` | `Textures\<Планета>\Archive\Elev.tree` | всегда |
| Маска жидкости | `Textures\<Планета>\Mask\<lvl:02>\<ilat:06>\<ilng:06>.dds` | — (архив не читается) | только у планет с жидкостью (`liq.has`) |

Слои `Cloud` (кроме не входящего в сборку `CloudLayer.cpp`), `Label`, `Elev_mod` не используются.

Маска: альфа 0 — жидкость. Для тайлов уровня ≥ 14 из альфы маски тайла и восьми соседей строится поле расстояния до
берега (R16F, `Planet::CoastField`, `Planet.cpp:488-551`): преобразование расстояний Фельценшвальба — Хуттенлохера,
сглаживание ~4 м, запас 32 текселя. Альфы масок кешируются (`MaskAlpha`, `Planet.cpp:458-485`, сброс при > 96 записях).
Подробнее — [water.md §2.11](water.md#2-физическая-модель).

### 6.3. Загрузка (`Planet::Load`, `Planet.cpp:572-752`)

- Потоки-загрузчики: `clamp(hardware_concurrency − 2, 2, 6)` (`Client.cpp:144-149`), функция `LoaderMain`
  (`Client.cpp:588-621`). Очередь выбирает тайл с наименьшим `prio` (`Planet::LoadPrio`, `Planet.cpp:826-832`:
  расстояние до камеры, делённое на размер тайла); тайл, не запрошенный 30 кадров, снимается с очереди. Пока
  компилируются шейдеры (последняя компиляция < 500 мс назад, `g_shaderTick`), загрузчики ждут
  (`Client.cpp:606-614`).
- Буферы файла, высот и вершин — `thread_local` у каждого потока-загрузчика и переиспользуются; рабочие буферы поля
  берега выделяются `VirtualAlloc` (`VAlloc`, `Planet.cpp:405-423`) — для сохранения адресного пространства 32-битного
  процесса.
- Тайл без своей текстуры рисуется подпрямоугольником текстуры ближайшего предка (`Planet::Draw`,
  `Planet.cpp:897-906`), маска — так же (`Planet.cpp:941-948`).
- Высоты: свои (`.elv` из файла или архива) либо билинейная интерполяция из высот ближайшего предка с данными
  (`Planet.cpp:608-630`). У берега жидкости свои высоты сглаживаются гауссом σ = 5 отсчётов в пределах 1 м от уровня,
  сдвиг не больше 6 см (`Planet.cpp:631-664`).
- **Хранение высот в 16 битах** (`ElevQ`, `Client.h:224-243`): 259×259 отсчётов как `base + step·q`, `q` — `uint16`,
  диапазон — собственный диапазон тайла. Полные высоты тайла сохраняются, только если хотя бы у одного ребёнка нет своих
  высот (ему понадобится интерполяция); тайл без своих данных хранит лишь ссылку на высоты владельца (`elevSrc`) и своё
  место в них (`esR`, `esC`, `esS`) (`Planet.cpp:665-684`). Узлы сетки 65×65 (`nodes`) хранятся всегда — для проверок
  высоты.
- Время стадий (чтение, декодирование + мипы, маска + берег, высоты, сетка) суммируется; строка
  `tile loads: N in T s (…/s) | ms each: …` раз в 10 с (`Planet::LoadStats`, `Planet.cpp:553-570`).
- Освобождение: тайл, не использованный 600 кадров и не занятый загрузчиком, удаляется; обход — раз в 64 кадра
  (`Planet::Purge`, `Planet.cpp:1058-1073`).

### 6.4. Разбиение и рисование (`Planet::Traverse`, `Planet.cpp:834-891`)

- Отсечение по горизонту (уровень > 5) и по пирамиде видимости (ограничивающая сфера).
- Разбиение: размер тайла на экране > `600·2^(−LodBias)` пикселей и `lvl < maxLevel`, причём хотя бы у одного ребёнка
  есть свои данные (текстура или высоты) **или** тайл на 1–2 уровня глубже последних данных высот
  (`lvl < elevLvl + 2`: сетка достигает полного разрешения данных, совпадая с поверхностью физики Orbiter).
- Дети рисуются от ближнего к дальнему; пока не загружены все четыре — рисуется родитель.
- Сетка: 65×65 узлов (каждый 4-й отсчёт) + «юбки» по краям, опущенные на `min(0.02·размер_тайла + 20 м,
  (emax − emin) + 4 м)` (`Planet.cpp:725-743`). Общий индексный буфер (`Client.cpp:415-447`) содержит полную сетку и
  сетку половинной плотности; половинная используется, если ячейка меньше 2.5 пикселя и у тайла нет материала грунта и
  поля берега (`Planet.cpp:977-986`; переменные `D3D11CLIENT_FINETILES`, `D3D11CLIENT_NOSKIRTS` — замеры).
- В тестовом режиме раз в 300 кадров — строки `elev check …` и `elev view …` (сравнение нарисованной поверхности с
  `oapiSurfaceElevation`, `Planet::ElevCheck`, `Planet.cpp:1024-1055`).

### 6.5. `.tree` (`TreeArchive`, `Planet.cpp:12-58`, `Client.h:198-212`)

```
смещение  тип       поле
0         DWORD     сигнатура 'T','X',1,0   (проверяется)
4         DWORD     размер заголовка = 48    (проверяется)
8         DWORD     не читается
12        DWORD     смещение начала данных (dataOfs)
16        INT64     длина данных (dataLen)
24        DWORD     число узлов N
28        DWORD×3   корни уровней 1, 2, 3
40        DWORD×2   корни уровня 4: запад, восток
48        N × 32 байта: INT64 pos; DWORD size (распакованный); DWORD child[4]  (−1 = нет)
```

Индекс узла: уровни 1–3 — свой корень; уровень 4 — `root[3 + (ilng & 1)]`; глубже —
`child[((ilat&1)<<1)|(ilng&1)]` родителя (`TreeArchive::Index`, `Planet.cpp:32-39`). `size == 0` — узел без данных.
Сжатый размер = `pos` следующего узла − `pos` (узлы предполагаются лежащими в файле по порядку), последний — до
`dataLen`. Чтение файла — под мьютексом архива, распаковка `oapiInflate` — вне его, в буфер потока
(`TreeArchive::Read`, `Planet.cpp:41-58`).

### 6.6. `.elv` (`ParseElev`, `Planet.cpp:369-381`)

```
0   char[4]  "ELE\x01"
4   int      размер заголовка (данные начинаются с него)
8   int      тип: -16 = INT16, 8 = UINT8, иное = плоский тайл (все значения = offset)
28  double   scale
36  double   offset          высота [м] = sample · scale + offset
данные: 259 × 259 отсчётов, строка 0 — юг, с рамкой в один отсчёт вокруг 257 × 257
```

Поля 12…27 и после 44 не читаются, размер 259 зашит в код. Файл короче 100 байт отвергается.

## 7. Каталог звёзд

`Config\CSphere\Data\star.bin` читается через `oapi::CelestialSphere::LoadStars()` (защищённый метод; обёртка
`StarLoader`, `Stars.cpp:6-13`). Отбор по яркости и цвета — по настройкам Orbiter внутри `Orbiter.lib`. Записи
`StarRenderRec {pos, col, brightness}` переводятся в структурированный буфер `StarGPU` по 32 байта (`CreateStars`,
`Stars.cpp:17-34`); строка журнала `stars: N`. Вызов — в `clbkPostCreation` (`Client.cpp:541`). Созвездия, подписи,
фоновое изображение неба не используются.

## 8. Текстуры (DDS)

`Dds.cpp`:

- Форматы: `DXT1` → BC1, `DXT2/3` → BC2, `DXT4/5` → BC3, `ATI1`/`BC4U` → BC4, `ATI2`/`BC5U` → BC5, заголовок `DX10` —
  формат как есть; несжатые 32 бит (BGRA/RGBA по маске красного), 24 бит, 16 и 8 бит по маскам каналов (флаг
  luminance — серый) (`LoadDDSMemory`, `Dds.cpp:263-366`).
- При `srgb = true` формат заменяется sRGB-вариантом (`ToSRGB`, `Dds.cpp:16-27`: BC1/2/3/7, RGBA8, BGRA8). Текстуры
  мешей, тайлов поверхности, микротекстуры без нормалей загружаются как sRGB; маски, карты нормалей и шероховатости —
  линейно.
- Сжатые: mip-цепочка из файла до первого неполного уровня. Если в файле один уровень, текстура BC1/BC2/BC3 и обе
  стороны ≥ 8, цепочка строится на CPU: декодирование, усреднение 2×2 в линейном пространстве для sRGB-каналов,
  повторное кодирование с концами по главной оси цветов блока (`BuildBlockMips`, `Dds.cpp:168-226`;
  `D3D11CLIENT_NOMIPGEN=1` отключает). Сжатые со сторонами, не кратными 4 (и ≥ 4), не грузятся.
- Несжатые: mip-цепочка боксом 2×2 на CPU без перевода в линейное пространство (`CreateTexture2D`, `Dds.cpp:368-395`).
- Кеш мипов: для файлов, загружаемых через `LoadDDSFile` (текстуры мешей, их карты, отдельные текстуры эффектов),
  построенная цепочка записывается в `Modules\D3D11Client\mipcache\<путь с заменой \ / : пробела на _>_<размер>_<время
  записи>.dds` и при следующем старте читается готовой (`MipCachePath`, `LoadDDSFile`, `Dds.cpp:231-261`). Тайлы
  поверхности загружаются через `LoadDDSMemory` и в кеш не пишутся.

Поиск текстур мешей (`clbkLoadTexture`, `Client.cpp:647-663`): `Textures2\`, `Textures\`, путь как есть; отсутствие —
строка `texture not loaded: …`. Сопутствующие карты по образцу D3D9Client (`MapsFor`, `Mesh.cpp:201-232`):
`<имя>_norm.dds` (линейно), `_spec` (sRGB), `_rghn`, `_metl` (линейно), `_emis` (sRGB) в `Textures2\`, затем
`Textures\`; строка `materials: <имя> with …`; `D3D11CLIENT_NOMAPS=1` отключает.
