# Дождь: Титан, Земля, капли на визоре

[← оглавление](DEVELOPER.md)

Состояние кода: 21.10.2026

Глава описывает три независимые системы:

| Система | Файлы | Где работает | Источник интенсивности |
|---|---|---|---|
| Метановый дождь Титана | `src\Rain.cpp`, `shaders\rain.hlsl` | тело камеры `Titan`, высота < 3 км, внутри круга `RainArea` | `Fx.cfg` `Rain` (мм/ч), постоянная величина |
| Дождь под циклоном Земли | `src\StormRain.cpp`, `shaders\storm_rain.hlsl` | тело шторма (`Storm.cfg` `Body`), под облаком шторма | погодная карта шторма (`Storm.cpp`, `StormAt`) |
| Капли на стекле шлема | `src\VisorDrops.cpp`, `shaders\visor_drops.hlsl` | корабли класса `OrbiterCrew*` (скафандры) | только дождь Титана (собственная копия разбора `Fx.cfg`) |

Облачные слои Титана (`Clouds.cpp`, `CloudLayer.cpp`, `Clouds.cfg`) с дождём не связаны: ни интенсивность, ни область
дождя из них не берутся (в `Clouds.cfg` морось упомянута только в комментарии). `Cyclone.cpp`, `CloudLayer.cpp`,
`EarthClouds.cpp` и `Cyclone.cfg` в сборку не входят (`build.bat`, строка 15) — дождя «у циклона» из `Cyclone.cfg`
в коде нет; дождь Земли существует только у шторма `Storm.cpp`.

## 1. Назначение и место в кадре

Порядок вызовов в `D3D11Client::clbkRenderScene` (`Client.cpp`):

| Строка | Вызов | Что рисует |
|---|---|---|
| 1010 | `RenderVessel(..., true)` | прозрачные группы чужих кораблей |
| 1011 | `RenderVisorDropsOutside` | капли на стёклах скафандров, вид снаружи |
| 1013 | `RenderStormShadow` | тень облаков шторма |
| 1014 | `FxRenderTransparent` | воздух (воздушная перспектива по глубине) |
| 1016–1021 | `RenderStorm`, `RenderClouds`, `LightsRenderAir` | облака шторма, облачные слои, лучи фар |
| 1023–1026 | `ExhaustRender`, `RenderAr`, `UpdateRenderParticles` | струи, AR-метки шлема, частицы |
| 1027 | `RenderRain` | дождь Титана |
| 1028 | `RenderStormRain` | дождь шторма Земли (+ брызги) |
| 1029 | `RenderUnderwater` | столб жидкости, если камера в ней |
| 1030 | `RenderVisorDropsInside` | симуляция капель на своём визоре и вид сквозь них |
| 1032–1044 | собственный корабль (`ownPass`) | кабина/шлем: тонировка визора, пластины шлемного дисплея, обод шлема — поверх капель |
| 1059 | `Render2DOverlay` | 2D-панели; HUD Orbiter и MFD — после возврата из `clbkRenderScene` (Sketchpad) |

Все проходы пишут в HDR-цель `hdrRTV` (R16G16B16A16F, при MSAA — многовыборочную) до резолва/TAA и тон-маппинга.
Капли на визоре изнутри лежат под тонировкой визора, пластинами дисплея шлема и HUD.

### 1.1 Дождь Титана (`RenderRain`, `Rain.cpp:46`)

- Цель: `hdrRTV` + `dsv` (глубина привязана, `dsRead` — тест без записи), растеризатор `rsNone`.
- Смешивание (`Rain.cpp:80–84`): премультиплицированное, `ONE / INV_SRC_ALPHA`, альфа цели не меняется
  (`ZERO / ONE`).
- Геометрия: без буферов, `DrawInstanced(6, n)` — по 6 вершин (2 треугольника) на каплю, `TRIANGLELIST`.
- Глубина сцены отсекает капли за объектами; поверхность жидкости пишет собственную глубину (`Liquid.cpp:363–370`),
  поэтому капли за ней тоже скрыты.
- После основного прохода — кольца на жидкости через `WakeRipple` (см. §3.1).

### 1.2 Дождь шторма (`RenderStormRain`, `StormRain.cpp:82`)

1. Compute: `CSInit` (при новом якоре) и `CSSim` (если шаг симуляции > 0) по `N_MAX / 256 = 768` групп.
2. `CopySceneColour(srScene)` (`AA.cpp:87`): резолв MSAA или копия HDR-цели в `srScene` + `ResolveDepth`.
3. Compute `CSEnv` (1 поток): яркость окружения для капель.
4. Капли: `DrawInstanced(4, active)`, `TRIANGLESTRIP`; брызги: `DrawInstanced(4, SPLASH_N)`.
- Цель: `hdrRTV` **без** буфера глубины (`StormRain.cpp:196`); перекрытие объектами — мягким затуханием по
  глубине сцены `depthSRV` в пиксельном шейдере (обратный Z).
- Смешивание: премультиплицированное (`ONE / INV_SRC_ALPHA`), то же, что у Титана.
- После прохода восстанавливаются прежние RTV/DSV (`StormRain.cpp:213`).

### 1.3 Капли на визоре

- Снаружи (`RenderVisorDropsOutside`, `VisorDrops.cpp:255`): `hdrRTV` + `dsv`, `dsRead`, `rsBack`, смешивание
  `bsPremul`, входной макет `ilOut` (вершины меша + буфер «положений покоя»). После прохода ставится `bsAlpha`.
  Рисуется до воздуха: `FxRenderTransparent` добавляет перспективу по глубине позади капель (капли глубину не пишут),
  сам `PSOut` вызывает `ApplyHaze`.
- Изнутри (`RenderVisorDropsInside`, `VisorDrops.cpp:353`): compute-симуляция, проходы во внутренние текстуры
  (плёнка, карта высот, линза, размытие), копия сцены в 1/4 разрешения с мипами, затем полноэкранный треугольник
  `PSInside` в `hdrRTV` без глубины (`bsPremul`). В конце восстанавливаются вьюпорт, `hdrRTV` + `dsv`, `bsOpaque`
  (`VisorDrops.cpp:689–693`).

## 2. Физическая модель

### 2.1 Титан (`rain.hlsl`, `Rain.cpp`)

**Параметры среды** (константы в коде, `rain.hlsl:22–26`, копия в `VisorDrops.cpp:92–97`):

| Величина | Значение | Единицы |
|---|---|---|
| g | 1.352 | м/с² |
| ρ жидкости (метан–этан) | 450 | кг/м³ |
| ρ воздуха | 5.4 | кг/м³ |
| μ воздуха | 6.2e-6 | Па·с |
| C_d | 0.6 («Re порядка сотен») | — |
| максимальный диаметр | 9.5 мм (Lorenz 1993: более крупные дробятся) | м |

**Конечная скорость** `Vt(d)` (`rain.hlsl:22`):

```
vN = sqrt(4 · g · d · (ρl − ρa) / (3 · Cd · ρa))      — баланс веса и сопротивления
vS = (ρl − ρa) · g · d² / (18 · μ)                     — Стокс
Vt = min(vN, vS)
```

Переход между ветвями — около d ≈ 0.2 мм. Значения: 1 мм — ≈ 0.50 м/с, 9.5 мм — ≈ 1.53 м/с (совпадает с
комментарием `Rain.cpp:3–4`: «~0.5 m/s at 1 mm, ~1.6 m/s at the largest»).

**Спектр размеров** — экспоненциальный (форма Маршалла–Палмера), с собственной зависимостью среднего от интенсивности
(`Rain.cpp:111`):

```
dMean = clamp(0.4 мм · max(I, 0.01)^0.21, 0.15 мм, 2.5 мм)      I — мм/ч
d     = min(−ln(u) · dMean, 9.5 мм),  u = Hash ∈ [1e-4, 1]       (rain.hlsl:34–35)
```

Коэффициент 0.4 мм в комментариях не обоснован (у Маршалла–Палмера среднее 1/Λ = I^0.21 / 4.1 мм ≈ 0.244·I^0.21 мм).

**Форма капли** не моделируется: капля рисуется штрихом вдоль скорости за выдержку 1/60 с (`k.p.w`), ширина —
не меньше ~0.7 пикселя (`w = max(0.5·d, dist · pixAngle · 0.7)`, `rain.hlsl:49`).

**Ветер.** Константа `rDrift` заполняется нулями (`Rain.cpp:114`), а в позиции ещё и умножается на 0
(`rain.hlsl:41`): дождь Титана падает строго вертикально.

**Ослабление/видимость в дожде** не реализованы: дождь не добавляет экстинкции воздуху.

**Источники в комментариях** (`Rain.cpp:1–9`): Huygens — дождя при посадке нет (январь 2005); морось ~50 мм/год
(Tokano et al. 2006); ливни у равноденствия (Turtle et al. 2011); капли до 9.5 мм (Lorenz 1993); летние дожди у
северных морей (Dhingra et al. 2019). Шкала из `Fx.cfg`: 0.5 — морось, 3 — дождь, 20 — шторм (мм/ч).

**Область.** Дождь идёт только в круге вокруг точки `RainArea` (по умолчанию 59.3335° N, 40.49° E — Kraken Mare,
радиус 60 км, затухание на последних 15 км). Интенсивность в точке камеры (`Rain.cpp:62–66`):

```
c   = sin φ · sin φ0 + cos φ · cos φ0 · cos(λ − λ0)
dkm = R · acos(c) / 1000
I   = Rain · clamp((Radius − dkm) / Fade, 0, 1)
```

### 2.2 Земля, шторм (`storm_rain.hlsl`, `StormRain.cpp`, `Storm.cpp`)

**Интенсивность из карты шторма** (`StormAt`, `Storm.cpp:709`). Карта погоды шторма (2048², каналы r — покрытие
`cov`, g — высота вершин `top`, b — доля конвекции `conv`, a — перистый щит) читается с CPU из копии мипа 3
(256², та же, что для турбулентности), билинейно (`CpuMap`):

```
depth = clamp((top − 2500 м) / 5000 м, 0, 1)                    — ливни только из глубоких облаков
eyeCut = clamp((r − 0.9·eyeR) / (0.2·eyeR), 0, 1), eyeR = 1.05·EyeKm   — в глазу сухо
mmh = cov² · (55·conv + 6·(1 − conv)) · depth · eyeCut          (Storm.cpp:726–728)
```

Дождя нет, если камера выше `top`, дальше `OuterKm` от центра или тело камеры не тело шторма. `StormRainHere`
(`Storm.cpp:695`) возвращает false, когда `C.rain` выключен. Порог «дождь есть» — `mmh > 0.05`.

**Ветер у камеры** (`Storm.cpp:730–749`): модифицированный вихрь Ранкина

```
rm = EyeKm + 0.5·EyewallKm, vmax = 62 м/с
vt = vmax · r/rm                    (r < rm)
vt = vmax · (rm/r)^0.6              (r ≥ rm)
vt *= clamp(0.8 + 0.2·h/2000, 0.8, 1)
ниже 300 м над грунтом (max(рельеф, 0)): vt *= clamp(ln(agl/z0) / ln(300/z0), 0.3, 1), z0 = 0.03 м
угол притока к центру: 20° ниже 1500 м, иначе 5°; вращение против часовой стрелки на севере (S.hs = ±1)
```

`alt` на выходе — высота камеры над грунтом (`agl`), из неё строится уровень земли в системе якоря.

**Порывы** (`Gust`, `storm_rain.hlsl:39`): медленная 3D-модуляция ветра, переносимая им, ≈ ±35 %:

```
q = p − wind·t
G = 1 + 0.22·sin(q·(0.071, 0.013, 0.053) + 0.9 t) + 0.13·sin(q·(−0.031, 0.02, 0.117) − 1.7 t)
vel = wind·G − (0, Vt(d), 0)
```

**Размеры** — Маршалл–Палмер (`StormRain.cpp:148`, `storm_rain.hlsl:35`):

```
Λ = 4.1 · max(R, 0.1)^−0.21   [1/мм]
d = clamp(−ln(u) / Λ, 0.5, 6.0) мм
```

Нижний предел 0.5 мм собирает в себе все мелкие капли (при R < ~30 мм/ч среднее 1/Λ < 0.5 мм).

**Скорость падения** — аппроксимация Atlas et al. (1973) (`storm_rain.hlsl:37`):

```
Vt(d) = max(9.65 − 10.3 · exp(−600 · d), 0.5) м/с,  d в метрах
```

(1 мм ≈ 4.0 м/с, 2 мм ≈ 6.5 м/с, предел 9.65 м/с.) Плотность и вязкость воздуха в формулу не входят.

**Число капель и прозрачность** (Garg & Nayar 2004/2005, Tremblay et al. 2020):

```
nReal = N0 / Λ,  N0 = 8000 м⁻³·мм⁻¹                — реальных капель в м³
nSim  = active / BOX³                              — частиц в м³
k     = max(nReal / nSim, 1)                       — реальных капель на одну частицу  (StormRain.cpp:157–158)
a1    = saturate((d / |v|) / T)                    — доля выдержки T = 1/60 с, которую капля закрывает пиксель
a     = (1 − (1 − a1)^k) · saturate(dpx / wpx + 0.25)   — k капель + покрытие тонкой линией
a    *= затухание к краю коробки и у камеры;  a ≤ 0.55          (storm_rain.hlsl:158–162)
```

`|v|` — скорость капли относительно камеры (не меньше 0.5 м/с).

**Освещение/вид капли** (`PSDrop`, `storm_rain.hlsl:173`):
- нормаль водяного цилиндра поперёк штриха: `n = normalize(x·side − sqrt(1 − x²)·V)`;
- Френель Шлика, `F0 = 0.02`;
- преломление: выборка сцены `srScene`, смещённая поперёк штриха на `x · clamp(2.5·ширина_px, 2, 14)` пикселей;
- окружение `env` (см. `CSEnv`, §6.2) ×(0.35 + 1.2 F) — капля собирает ~165° окружения и ярче тёмного фона;
- Солнце вперёд: `SunLight · StormCameraLight() · HG(g = 0.8, cos) · 0.06`;
- итог: `behind·(1 − F)·0.85 + env·(0.35 + 1.2 F) + sun`, премультиплицированный на `a`.

`StormCameraLight` (`Storm.cpp:663`) — доля дневного света под облаками: `1 / (1 + 0.11 τ)`, τ по столбу карты,
сглаживание ~1.5 с; в дожде умножает только солнечный член.

**Ослабление/видимость в дожде** как отдельный член не реализовано; затемнение и туман дают сами облака шторма
(`RenderStorm`).

**Источники в комментариях** (`StormRain.cpp:1–6`, `storm_rain.hlsl:1–11`): Wicked Engine (MIT) — частицы на GPU в
коробке у камеры, штрих по относительной скорости, «линза» с френелевым ободом, мягкое затухание по глубине, брызги,
блокировщик вокруг персонажа; Garg & Nayar; Tremblay et al. (IJCV 2020); Marshall–Palmer; Atlas et al. (1973).
Код собственный.

### 2.3 Брызги

- **Земля** (`CSSim`, `storm_rain.hlsl:70–80`): капля, ушедшая ниже уровня грунта `rL.z`, с вероятностью 1/4 и
  в радиусе 18 м от камеры (по горизонтали) записывает брызги в кольцевой буфер (`InterlockedAdd` счётчика,
  индекс по модулю `SPLASH_N`); капля переносится на высоту коробки вверх с новым диаметром. Брызги (`VSSplash`,
  `PSSplash`): вертикальная «корона» лицом к камере, 3.5–8 см, живёт 0.14 с, прозрачность
  `(1 − k)² · saturate((18 − dist)/6) · saturate(R/10) · 0.6`, цвет `env · 1.1`. Тип поверхности (суша/море) не
  различается.
- **Титан**: брызг на грунте нет; капли, падающие в жидкость, дают кольца волн (`WakeRipple`, `Rain.cpp:131–144`):
  при камере не выше 1500 м над уровнем жидкости, в круге 20 м вокруг фокусного корабля,
  `min(120, I·40 + U)` колец **за кадр**; радиус `max(0.015, 4d)` м, амплитуда `clamp(d / 1 мм, 0.2, 2)`.
  Очередь `WakeRipple` ограничена 256 толчками за кадр (`Wake.cpp:204`).

## 3. Данные и поток данных

### 3.1 Титан — без хранимого состояния

- Капля полностью процедурна: индекс экземпляра → `Hash` → положение в коробке со стороной `B = 40 м`, диаметр, блик.
- Коробка «привязана к грунту»: якорь `rnA` (точка у камеры в системе планеты, double) и оси `rnE1, rnUp, rnE2`;
  якорь переносится, когда камера отходит от него на 5 км (`Rain.cpp:90`). Смещение камеры по осям якоря берётся
  по модулю `B` на CPU (`k.off`), чтобы во float оставались малые числа.
- В шейдере: `q = h·B − off; q.y −= Vt·t; q = q − B·floor(q/B) − 0.5·B` — капли падают и заворачиваются вокруг
  камеры (`rain.hlsl:38–40`). Время — `fmod(simt, 3600)`.
- Отбрасываются капли ближе 0.4 м и ниже уровня жидкости под камерой (`rUp.w` — высота камеры над жидкостью,
  1e9 если её нет).
- Число экземпляров `n = clamp(I·20000, 4000, 90000)` (`Rain.cpp:127`); прозрачность `rP.z = clamp(0.5 + 0.25·I, 0.5, 2)`,
  на каплю `a = rP.z · (0.18 + 0.3·saturate(d/3 мм)) · затухание(dist)`; затухание от 25 до 40 м (на практике
  до половины диагонали коробки, ≈ 34.6 м).
- Свет (`rain.hlsl:63–66`): `SkyLight(up)·0.9 + SkyLight(−up)·0.3`, у ~7 % капель (`Hash > 0.93`) — блик
  `SunLight · ShadowAt · 0.8 · (0.5 + 0.5 cos)`; цвет вычисляется в VS (`nointerpolation`).
- Ресурсы: VS, PS, константный буфер 160 байт, состояние смешивания. Карта теней — в VS (`t7`, `s2`).
- Затраты CPU: условия + одна запись константы + до 120 вызовов `WakeRipple`; GPU — 6·n вершин. Таймеров нет.

### 3.2 Земля — частицы на GPU

| Ресурс | Размер / формат | Назначение |
|---|---|---|
| `bDrops` | `N_MAX = 196608` × 16 Б (`float3 p; float d`), structured, UAV+SRV | капли, ~3 МБ |
| `bSplash` | `SPLASH_N = 8192` × 16 Б (`float3 p; float t0`) | кольцо брызг |
| `bCount` | 16 Б, raw UAV | счётчик кольца брызг (не обнуляется, работает по модулю) |
| `bEnv` | 1 × 16 Б | свет окружения (`CSEnv`) |
| `srScene` | RW × RH, R16G16B16A16F | копия сцены для преломления (пересоздаётся при смене размера) |
| `srCB` | `struct CB` (матрица + 11 float4 = 240 Б), dynamic | константы `b1` |

- Якорь (`srA`, оси `srE1/srUp/srE2`) закреплён на грунте; при отходе камеры на 30 км или смене тела — новый якорь и
  пересоздание всех капель (`CSInit`). Коробка `BOX = 26 м`, центр на `0.15·BOX` выше камеры
  (`BoxCentre`, `storm_rain.hlsl:51`); капли заворачиваются вокруг неё (`CSSim`), эмиттера нет.
- Активных частиц `active = N_MAX · clamp(R/60, 0.03, 1)` (`StormRain.cpp:149`); симулируются все `N_MAX`,
  рисуются первые `active`.
- Интенсивность у камеры плавно следует за картой: `srRate += (target − srRate)·(1 − exp(−dt/2 с))` по системному
  времени; ниже 0.05 мм/ч проход не выполняется (`StormRain.cpp:91–92`).
- Скорость камеры над грунтом — по разности положений в системе планеты за шаг симуляции, сглаживание 0.3
  (`StormRain.cpp:117–124`); штрих строится по скорости капли **относительно камеры** (`VSDrop`).
- Шаг симуляции `rWind.w = min(simDt, 0.05)`; `simDt = 0` при паузе и при шаге симуляции ≥ 1 с (сильное ускорение
  времени) — тогда капли стоят.
- Блокировщик: фокусный корабль размером 0 < size < 3 м внутри коробки — цилиндр радиуса `0.45·size`, высотой
  `1.9·size` от уровня `−0.9·size` (`StormRain.cpp:129–138`); капли внутри него не рисуются (`VSDrop`).
- Затраты: CPU сглаженно пишется в лог (весь проход и запрос карты, мс); GPU-таймеров у прохода нет. Каждый кадр
  с дождём — полная копия/резолв HDR-цели и глубины.

## 4. Капли на визоре: модель

### 4.1 Кто и когда

- Вид изнутри — фокусный корабль класса `OrbiterCrew*` со стеклом: группа с прозрачностью материала 0.01 < a < 0.99
  без флагов `4 | 8 | 0x100` (`GlassGroup`, `VisorDrops.cpp:151`) или VC-меш, у которого группа 0 несёт `UsrFlag 0x100`
  (светофильтр визора, «пластина»). OrbiterCrew ставит `0x400` на группу 0 пластины, пока шлем закрыт и взгляд свой;
  после первого появления флага (`closedFlagKnown`) рисование изнутри требует его (`VisorDrops.cpp:368–387`).
- Симуляция идёт, пока `I > 0`, или стекло только что вышло из жидкости, или с последнего удара прошло < 1500 с,
  или живы капли (`VisorDrops.cpp:401`); под жидкостью (голова ниже уровня + 0.02 м) — пропуск; при выходе —
  «слив»: 250 крупных капель (2–32 мм³) и 150 бусин (`VisorDrops.cpp:525–531`).
- Смена фокуса — сброс состояния (`S = Sim()`), очистка плёнки и буфера капель.

### 4.2 Входы (CPU, `VisorDrops.cpp:404–442`)

- Ускорение: `gEff = −up · GM/r² − aCam`; `aCam` — ускорение головы по второй разности положений камеры
  (ограничение 25 м/с², сглаживание 0.3) — толчки при ходьбе.
- Воздух: `GetAirspeedVector(FRAME_GLOBAL)` скафандра; плюс ветерок `VisorDropsWind` в горизонтальной плоскости,
  направление `0.6 + 1.5·sin(0.021 t)` рад, порывистость `1 + 0.35·sin(0.53 t)·sin(0.21 t + 1)`.
- Тестовая добавка `VisorDropsTestAir` (м/с вдоль взгляда, только `testMode`).
- Все векторы переводятся в систему скафандра.

### 4.3 Удары (CPU)

```
q      = I / 3.6e6                         — м³ дождя на м² в секунду
Vmean  = π · dMean³                        — <π d³ / 6> для экспоненциального спектра
nd     = q / (Vmean · Vt(1.5·dMean))       — капель в м³ воздуха
vrel   = down · Vt(1.5·dMean) + airC       — капли относительно стекла
flux   = Σ max(0, −vrel·n) · dA  по сетке 32 × 20 участков стекла
ударов/с = nd · flux;  за кадр: acc += nd·flux·dt·(0.5 + U)
```

`dMean` и `Vt` — те же формулы, что у дождя Титана (`VisorDrops.cpp:91–97`). Место удара — выборка с отклонением
по `−vrel·n·dA`, размер — экспоненциальный спектр, объём `π d³/6`. Разбрызгивание по критерию Мундо:

```
We = ρl · d · un² / σ,  Re = ρl · un · d / μl,  K = sqrt(We) · Re^0.25
K > 57: 35 % объёма остаётся в точке, 65 % — в ns = clamp(K/12, 3, 10) капель-спутников,
        разлетающихся с наклоном по касательной скорости, на расстояние d·(0.8 + 0.03K)·(0.3 + U)
```

Капли < 0.02 мм³ идут бусинами в плёнку; объём ограничен 400 мм³. За кадр — не более `MAXSPAWN − 12` ударов.

### 4.4 Симуляция (GPU, `visor_drops.hlsl`)

Параметры (`VisorDrops.cpp:27–29`): σ = 0.017 Н/м, ρl = 450 кг/м³, μl = 1.8e-4 Па·с, ρ воздуха 5.4 кг/м³,
краевой угол 55° (олеофобное покрытие визора), капиллярная длина 5 мм, испарение капли 0.002 мм²/с, плёнки
0.0003 мм/с.

- **Форма** (`Cap`, строка 95): сферическая шапка `V = k R³`, `k = π(2 − 3cosθ + cos³θ)/(3 sin³θ)`, `h = R·tan(θ/2)`;
  при `h > 2·lc·sin(θ/2)` (≈ 4.6 мм) — лужица этой высоты, `R = sqrt(V / (0.9 π h))`. Профиль (`Profile`) —
  смесь шапки и лужицы с плоским верхом.
- **Слияние** (`CSClearGrid`, `CSInsert`, `CSUpdate`): крупнейшая капля каждой ячейки 16×16 текселей; капля,
  касающаяся (`dist² < 0.8 (R + Ro)²`) более крупной из 3×3 соседних ячеек, поглощается ею (`InterlockedAdd` в
  `volAdd`, добавка в `CSFinalize`).
- **Силы** (строки 183–191): `F = m·(gEff·eu, gEff·ev)`; воздух — касательная составляющая потока, ×1.5 с
  наветренной стороны, ×0.35 с подветренной, сопротивление `0.5 ρa · 1.2 · |u| u · (2 R h)`.
- **Пиннинг** (строки 195–197): `pin = σ · 2R · VisorDropsPin · Hetero(0.6…1.4) · seed(0.8…1.2)`, на мокром следе
  до ×0.45, у движущейся капли ×0.7. При `|F| > pin` — скольжение `v = dir · min((|F| − pin) / (45 μl R), 3 м/с)`,
  направление слегка отклоняется градиентом неоднородности; скорость релаксирует с `saturate(25 dt)`.
- **След**: капля забирает плёнку `0.6 · film · 2R · путь`; через каждые `R·(1.5 + 1.5 seed)` пути (при V > 0.3 мм³)
  оставляет бусину 1.5–4 % объёма.
- **Испарение**: `dV = 0.002 мм²/с · R · dt`; смерть при V < 0.004 мм³ или у края сетки. Плёнка: `−0.0003 мм/с`
  (`CSFilm`).
- **Новые капли** (`CSSpawn`): слот кольца `S.ring % NDROP`; прежняя капля слота остаётся бусиной.

### 4.5 Изображение изнутри

1. Плёнка (`VSDrop` + `PSWipe`, умножение): движущаяся капля стирает плёнку до 8 % в центре; `PSBead` (max) — бусины
   капель и бусины ударов. Капля вытянута вдоль скорости: `e = 1 + min(6|v|, 3)`, оси `R·√e` и `R/√e`.
2. Карта высот (`PSCopyFilm` → `PSCap`, max).
3. `PSLens`: наклоны по центральным разностям в мм/мм, покрытие `smoothstep(0.004, 0.03, h)`.
4. Расфокусировка глазом (`PSBlurH`, `PSBlurV`): гаусс по следу зрачка на стекле, σ = 0.35 · зрачок / размер текселя,
   0.5–10 текселей, радиус ≤ 24.
5. Копия сцены 1/4 (`PSDown` / `PSDownMS` — две выборки MSAA), `GenerateMips` (5 уровней).
6. `PSInside` (строка 422): луч пикселя → азимут/возвышение → тексель; бикубическое чтение линзы;
   нормаль капли `Nd = normalize(n − VisorDropsRefraction·(sx·eu + sy·ev))`; `refract(d, −Nd, 1.28)`;
   полное внутреннее отражение (критический угол ≈ 51°) — тёмный обод (`sky·0.04`); сцена сквозь каплю из мипа
   `3·saturate(1.5·|s|)`, за краем копии — небо; пропускание 0.955; Солнце и до 4 локальных ламп — мягкие диски
   `GGX(α = 0.035) · α² π · VisorDropsGlint · saturate(3|s| + 0.2)` (без теней).

### 4.6 Вид снаружи

Для каждого скафандра в пределах 60 м (кроме своего при виде изнутри) — влажность `wet`: цель
`clamp(0.35 + 0.2 I, 0.35, 1)` при дожде, намокание τ = 40 с, высыхание τ = 600 с (`VisorDrops.cpp:270–275`).
Стеклянные группы рисуются повторно с буфером «положений покоя» (вершины, как впервые прочитаны: капли не ползут
при скиннинге). `PSOut` (строка 496): ячейки 3.5 мм в системе покоя, в ячейке капля с вероятностью `0.9·wet`,
радиус 0.18–0.55 ячейки; Френель `F0 = 0.0155`, отражение неба, блик Солнца (GGX α = 0.004, тень), локальные огни;
прозрачность `cov · lerp(0.12, 0.7, rr²)`, дымка `ApplyHaze`.

## 8. Ограничения, известные проблемы, расширение

### 8.1 Ограничения и расхождения

- **Ветра у дождя Титана нет**: `rDrift = 0` (`Rain.cpp:114`) и множитель `0.0` в `rain.hlsl:41`, при этом капли на
  визоре сносит ветерок `VisorDropsWind` 0.6 м/с — дождь в воздухе вертикален, на стекле косой.
- **Кольца на жидкости зависят от частоты кадров**: `min(120, I·40 + U)` колец за кадр, не за секунду
  (`Rain.cpp:138`).
- **Комментарий устарел**: `rain.hlsl:43` «its pass writes no depth» — поверхность жидкости теперь пишет глубину
  (`Liquid.cpp:363`); проверка `q.y + rUp.w < 0` дублирует тест глубины.
- **Визор знает только дождь Титана**: `RainAt` читает `Fx.cfg`; дождь шторма Земли стекло не мочит.
- **Дублирование кода**: разбор `Rain`/`RainArea`, `DropMean` и `Vt` повторены в `VisorDrops.cpp:61–97` и
  `rain.hlsl:22`; правки нужно вносить во все копии.
- **Шторм**: код по умолчанию держит `Rain = 0` с комментарием «off until it is redone after a proper reference»
  (`Storm.cpp:28`), а `Storm.cfg` его включает; на 20.10.2026 дождь шторма был выключен как
  неудовлетворительный; текущая реализация (Wicked/Garg–Nayar) сделана позже. Является ли она принятой, по коду не ясно.
- **Шторм, ускорение времени**: при шаге ≥ 1 с `simDt = 0`, капли не движутся (`StormRain.cpp:119`).
- **Шторм, размеры**: нижний предел 0.5 мм сдвигает спектр при слабом дожде.
- **Шторм, брызги** одинаковы на суше и на море; поверхность моря Земли ими не возмущается.
- **Видимость/экстинкция в дожде** нигде не моделируется.
- **Время** в шейдерах — `fmod(simt, 3600)`: раз в час фаза всех капель Титана скачком меняется.
- **Капли не имеют векторов движения**: при TAA (`AntiAliasing = 5`) возможны следы; не проверено.
- **Визор при выключенном HUD** (клавиша H): пластина становится `MESHVIS_NEVER`, флага `0x400` нет — капли изнутри
  не рисуются (замечено 20.10.2026).
- **Комментарии `visor_drops.hlsl`**: строка 11 — «8 x 8 texel cell», в коде `GRIDC = 16`; строка 352 — «half size»,
  копия в 1/4; строки 365–366 — «two samples» и «one sample» к одному коду (две выборки).
- `VisorDropsWind` не выводится в строку конфигурации журнала.
- Все конфигурации дождя читаются один раз за процесс Orbiter: изменения `Fx.cfg`, `Storm.cfg`, `VisorDrops*`
  вступают в силу после перезапуска Orbiter.exe (кроме галочки `VisorDrops` в диалоге).
- TODO-комментариев в файлах дождя нет.

### 8.2 Как добавить дождь для другого тела

Дождь «у камеры» с постоянной интенсивностью (по образцу Титана):

1. Имя тела зашито в `Rain.cpp:53` и `VisorDrops.cpp:81` (`_stricmp(nm, "Titan")`). Для нового тела нужно
   заменить проверку на таблицу тел (например, ключ `RainBody` или раздел в `<Body>.cfg`) — сейчас такого ключа нет.
2. Параметры среды — константы в `rain.hlsl:24–25` (`Vt`) и `VisorDrops.cpp:94–95`: g, ρ жидкости, ρ воздуха, μ
   воздуха, C_d; передавать их через `cbuffer Rain` (свободных компонент нет — буфер нужно расширить; размер 160 Б
   задан в `Rain.cpp:78`).
3. Спектр: `dMean` (`Rain.cpp:111`, `VisorDrops.cpp:91`) и предел 9.5 мм (`rain.hlsl:35`, `Rain.cpp:141`,
   `VisorDrops.cpp:500`).
4. Свойства жидкости для визора — `SIGMA`, `RHO_L`, `MU`, `CONTACT`, `LCAP_MM`, испарение (`VisorDrops.cpp:27–29`);
   показатель преломления 1.28 — в `visor_drops.hlsl:447` и `:522`.
5. Область — `RainArea` (одна на всё; нужен список для нескольких тел).

Дождь из погодного поля (по образцу Земли): реализовать функцию вида
`bool XxxRainHere(const VECTOR3& cp, double& mmh, VECTOR3& wind, double& alt)` и вызывать её вместо
`StormRainHere` в `StormRain.cpp:87`; скорость падения (`storm_rain.hlsl:37`) — земная (Atlas), без плотности воздуха,
для другого тела её нужно заменить.
