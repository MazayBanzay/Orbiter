# Шейдеры

[← оглавление](DEVELOPER.md)

Исходники — `shaders\`, устанавливаются в `Modules\D3D11Client\` и компилируются **при создании окна рендера**
(`D3DCompileFromFile`, `vs_5_0` / `ps_5_0`, `D3DCOMPILE_OPTIMIZATION_LEVEL3`, `#include` относительно файла):
основные — `D3D11Client::CreateShaders` (`Client.cpp`), эффекты — `FxCompile` (`Fx.cpp`). Точки входа: `VS` и `PS`
(в `aa.hlsl` — `VS`, `ResolveDepthPS`, `TAAPS`, `FXAAPS`). Ошибки и предупреждения компилятора пишутся в `Orbiter.log`
(`shader <путь> <вход>: …`); если не собрался хоть один основной шейдер, сцена не рисуется (`shadersOk = false`).
Поэтому правка установленного `.hlsl` вступает в силу при следующем запуске сессии, без пересборки DLL.

## Соглашения

- Матрицы на CPU транспонируются перед записью, в HLSL `mul(float4(p,1), M)` — строчные векторы
  (см. [architecture.md §4](architecture.md#4-системы-координат-и-матрицы)).
- «Мировые» позиции (`wp`, `WPOS`) — глобальная система, сдвинутая в камеру (камера в нуле).
- Цвет сцены — линейный HDR (R16G16B16A16F); sRGB-кодирование делает RTV back buffer'а.
- Полноэкранные проходы — треугольник из `SV_VertexID` (3 вершины, без буферов) — `sky`, `post`, `blit`, `aa`, `fx_atmo`.

## Регистры

| Слот | Что | Кто ставит |
|---|---|---|
| `b0` | `Frame` (`common.hlsli`) — VS и PS | `UpdateFrameCB` раз в кадр (`Client.cpp`) |
| `b1` | константы объекта/прохода; один динамический буфер `cbObj` на 512 байт, перезаписывается `Map(DISCARD)` перед каждым draw | `RenderVessel`, `Planet::Draw`, `RenderStars`, `UpdateRenderParticles`, `RenderLiquid`, `clbkRender2DPanel`, AA-проходы |
| `b3` | `Atmo` (`fx_atmo.hlsl`) — собственный буфер эффекта | `FxAtmoRender` |
| `t0` | основная текстура прохода (диффузная, тайл, сцена, источник blit/AA; в VS звёзд — `StructuredBuffer`) | у каждого прохода |
| `t1` | глубина сцены (одновыборочная, R32F) — жидкость, TAA | `RenderLiquid`, `FinishScene` |
| `t2`, `t3` | история TAA, вектора движения | `FinishScene` |
| `t7` | карта теней (PS) | `clbkRenderScene` |
| `s0` | анизотропный, WRAP | `clbkRenderScene` (PS) |
| `s1` | анизотропный, CLAMP (`sampClamp`) | `clbkRenderScene`; 2D-проходы ставят сами |
| `s2` | сравнивающий (тени), BORDER = 1, `LESS_EQUAL` | `clbkRenderScene` |

`cbGrp` (256 байт) создаётся в `CreateDevice`, но нигде не используется.

## `common.hlsli` — общее

`cbuffer Frame : register(b0)` (C++-зеркало — `struct FrameCB`, `Client.cpp`):

| Поле | Смысл |
|---|---|
| `float4x4 gInvVP` | клип → сдвинутая в камеру глобальная система |
| `float4 gSunDir` | направление на Солнце (глобальное); `w` — «день» у камеры 0…1 (Солнце от −5° до ~+10° над горизонтом) |
| `float4 gSky0` | цвет горизонта; `w` = 1, если камера в атмосфере |
| `float4 gSky1` | цвет зенита; `w` — сила неба (угасает с высотой: `exp(−alt / 2.5·ScaleHeight)`) |
| `float4 gAmb` | свет неба на поверхностях; `w` — экстинкция дымки у земли [1/м] (× `Haze`) |
| `float4 gSun` | цвет прямого Солнца в атмосфере; `w` — высота однородной дымки [м] |
| `float4 gUp` | местная вертикаль у камеры; `w` — высота камеры [м] |
| `float4 gPlanet` | центр планеты от камеры; `w` — радиус |
| `float4 gHazeRGB` | спектральные веса экстинкции; `w` — экспозиция |
| `float4x4 gLightVP` | сдвинутая глобальная → карта теней |
| `float4 gShadow` | `x` — тени есть, `y` — размер текселя |

Ресурсы: `Texture2D<float> tShadow : t7`, `SamplerComparisonState sShadow : s2`. Функции:

| Функция | Что делает |
|---|---|
| `ShadowAt(wp)` | видимость Солнца: PCF 3×3 по карте теней; 1 вне карты или если теней нет |
| `SkyColour(dir)` | небо: горизонт→зенит по `pow(saturate(dir·up), 0.6)`, подсветка горизонта к Солнцу, ореол Солнца (`pow` 24 и 400), × день × сила неба |
| `ApplyHaze(col, wp)` | воздушная перспектива: Бугер–Ламберт вдоль луча, экстинкция `gAmb.w · gHazeRGB · exp(−h̄/H)` по средней высоте луча; рассеянный свет = цвет горизонта × день × сила неба. Вне атмосферы — без изменений |
| `SunLight()` | цвет прямого Солнца: `gSun.rgb` в атмосфере, белый в космосе |
| `SkyLight(n)` | свет неба на нормаль `n` (`gAmb` × 0.35…1 по наклону × день × сила неба); в космосе — 0.02 |

## Файлы

### `mesh.hlsl` — корабли
- `b1 Obj`: `gWVP`, `gW` (в сдвинутую глобальную), `gSunM` (на Солнце), `gDiff`, `gMAmb`, `gSpec` (`w` = степень),
  `gEmis`, `gFlags` (`x` — есть текстура, `y` — вид из кабины: передаётся, в шейдере не используется), `gCurNJ`,
  `gPrevNJ` (WVP этого и прошлого кадра без джиттера TAA — для векторов движения). C++: `struct MeshCB` (`Mesh.cpp`).
- `t0` диффузная, `s0`. Вход — `NTVERTEX` (`POSITION`, `NORMAL`, `TEXCOORD`), раскладка `ilMesh`.
- PS: `base = gDiff × текстура`; `base·(N·L·тень·SunLight + SkyLight + 0.02·ambient) + emissive` + Блинн–Фонг;
  `ApplyHaze`; альфа = `base.a`. Выход: `SV_Target0` — цвет, `SV_Target1` — вектор движения (uv сейчас − uv тогда;
  пишется, только когда привязан второй RT — при TAA в непрозрачном проходе).
- Используется и для теней (тогда PS не ставится, только глубина).

### `planet.hlsl` — тайлы
- `b1 Tile`: `gWVP`, `gSunL` (Солнце в системе планеты — в PS не используется), `gUV` (масштаб/сдвиг uv для текстуры
  предка), `gMisc` (`x` — есть текстура, `y` — уровень), `gW` (тайл → сдвинутая глобальная), `gRot` (система планеты →
  глобальная, для нормалей). C++: `struct PlanetCB` (`Planet.cpp`).
- `t0` текстура тайла, выборка через `s1` (CLAMP; `s0` объявлен, но не используется). Вход — `TileVertex`
  (`POSITION`, `NORMAL`, `TEXCOORD`), та же раскладка, что у мешей (`ilPlanet`).
- PS: альбедо (серое 0.5 без текстуры) × (N·L·тень·SunLight + SkyLight); из космоса — мягкий терминатор
  `0.05·smoothstep`; `ApplyHaze`.

### `sky.hlsl` — небо
Полноэкранный; направление из `gInvVP` на глубине 1e−7 (почти бесконечность), цвет `SkyColour`. Рисуется, только если
камера в атмосфере. Без `b1`.

### `stars.hlsl` — звёзды
- `b1 Stars`: `gSVP`, `gSMisc` (2/W, 2/H, видимость). `t0` (VS) — `StructuredBuffer<Star>` {dir, b, col, pad} (32 байта).
- 6 вершин на звезду (`SV_VertexID / 6`), квадрат ±1.2 пикселя вокруг `dir·1e6`, `z = 0` (бесконечность при обратном Z).
  Цвет `col · saturate(1.4·b) · видимость`; PS — круглое затухание; смешение аддитивное.

### `particles.hlsl` — потоки частиц
- `b1 Part`: `gPVP`, `gPFlags` (`x` — излучающий). `t0` текстура частицы, `s1`. Вход `PVert` (`POSITION`, `TEXCOORD`,
  `COLOR`), квадраты строятся на CPU.
- Излучающие: `float4(t.rgb·a, a)` при смешении `bsAdd` (`SRC_ALPHA, ONE`) — т.е. альфа фактически применяется дважды
  (`rgb·a²`); задумано ли так — по коду не ясно. Диффузные: `t.rgb·(0.6·SunLight + SkyLight(0) + 0.05)`, `ApplyHaze`,
  `bsAlpha`.

### `liquid.hlsl` — жидкость (⚠ файл у сессии эффектов)
- `b1 Liquid`: `gVP`, `gLInvVP`, `gBase` (камера → точка жидкости под ней; `w` — радиус сферы жидкости), `gLUp` (`w` —
  радиус сетки), `gE1`, `gE2` (касательные оси), `gColour` (`w` — экстинкция), `gWts` (`w` — показатель преломления),
  `gLMisc` (`x` — время). C++: `struct LiquidCB` (`Liquid.cpp`).
- `t0` копия цвета сцены, `t1` глубина, `s1`. Вход — `float2 POSITION` (доля кольца, доля угла).
- VS: кольца растут геометрически от 0.3 м до радиуса сетки; точка сферы из малых слагаемых (без потери точности).
  Компилятор предупреждает `X3571` о `pow` с возможно отрицательным основанием (строка ~27).
- PS: лёгкая рябь; Френель (F0 из показателя преломления); отражение неба `SkyColour`; преломление — 3 шага по
  преломлённому лучу с поиском дна в глубине сцены; Бугер–Ламберт по каналам; рассеянный в жидкости цвет; блик GGX с
  тенью; `ApplyHaze`. Глубина в проходе привязана только для чтения (read-only DSV), поэтому тест глубины и чтение
  в одном проходе.

### `panel.hlsl` — 2D-панели
- `b1 Panel`: `gXf` (масштаб x, y, сдвиг x, y — из `MATRIX3 T`), `gMisc` (2/W, 2/H, альфа). `t0`, `s1`.
- Вход — `NTVERTEX` (раскладка `ilMesh`), координаты в пикселях панели → NDC. PS: текстура × альфа.

### `post.hlsl` — тон-маппинг
`t0` — HDR (или результат резолва/TAA), читается `Load` по пикселю; × экспозиция (`gHazeRGB.w`); мягкое «плечо»
`c / (1 + max(c − 0.8, 0)·0.5)` — почти линейно, чтобы текстуры Orbiter выглядели как задуманы. Пишет в sRGB-RTV back
buffer'а (или в промежуточную LDR-текстуру при FXAA).

### `blit.hlsl` — копия текстуры
`t0`, `s1`, `SampleLevel(…, 0)` на весь экран. Используется для композиции слоя экрана (с `bsAlpha`) и для `Readback`
(чтение пикселей файловой текстуры в DIB).

### `aa.hlsl` — сглаживание (⚠ файл у сессии сглаживания)
- `b1 AA`: `gInvVP` (этот кадр, с джиттером), `gPrevVP` (прошлый кадр, без джиттера), `gCamDelta` (сдвиг камеры
  относительно ближайшего тела), `gP` (`x` — вес истории 0.9, `y` — история годна, `zw` — 1/размер). C++: `struct AACB` (`AA.cpp`).
- `ResolveDepthPS`: `Texture2DMS<float>` t0 → R32F, берётся выборка 0.
- `TAAPS`: t0 текущий кадр, t1 глубина, t2 история, t3 вектора движения; репроекция через глубину (небо — без параллакса),
  у кораблей — их вектора движения; ограничение истории окрестностью 3×3 в тон-маппированном пространстве.
- `FXAAPS`: класс FXAA — по яркости, смешение вдоль края; работает по уже sRGB-кодированному LDR-изображению.

### `fx_atmo.hlsl` — атмосфера снаружи (⚠ файл у сессии эффектов)
- `b3 Atmo` (C++: `struct AtmoCB`, `FxAtmo.cpp`): строки поворота камеры, тангенсы полуугла, центр планеты, высоты,
  Солнце + асимметрия g, экстинкция по каналам, альбедо однократного рассеяния, амплитуда многократного рассеяния,
  затухание диффузного света, солнечный свет у земли. `t0` — глубина сцены. Включает `common.hlsli`.
- Полноэкранный проход на каждую планету с атмосферой в поле зрения (дальние первыми): экстинкция того, что позади
  (по глубине), однократное рассеяние (Хеньи–Гринстейн, функция Чепмена для пути к Солнцу — терминатор, сумерки,
  ночная сторона) + многократное (формула подобия ван де Хюлста). Два выхода (`SV_Target0` — добавка, `SV_Target1` —
  множитель) и **dual-source blending** (`ONE`, `SRC1_COLOR`). В атмосфере ослабляется по мере того, как работают
  собственные небо и дымка клиента.
